system startup

该章以x86架构为例，讲述linux在x86架构的计算机中的开机过程

BIOS

当给计算机按下开机键后，cpu的reset引脚会被 raise，cpu中的cs，eip等寄存器被set to fixed value.然后，物理地址0xfffffff0处的代码被执行。这个地址被映射到 read-only, persistent memory chip, 也就是ROM. 存储在ROM的程序叫做Basic Input/Output System (BIOS)。

在使用BIOS时，cpu处于real mode, 其寻址单元不依赖 Global Descriptor Table， Local Descriptor Table, or paging table，只需要段地址和偏移地址，the corresponding physical address is given by seg*16+off. 在初始化好 GDT, LDT, and paging tables之前，cpu的寻址模式都处于实模式。

BIOS主要做以下4件事

  • 执行一系列测试来确定计算机硬件上存在哪些设备以及它们是否正常工作，然后构建系统中关于硬件设备的表格，操作系统会读取这些表格，了解如何处理其硬件。
  • 初始化硬件设备。在现代基于PCI的架构的计算机中，这个阶段非常关键，因为它保证所有硬件设备在IRQ线和I/O端口上无冲突地运行。在此阶段结束时，会显示已安装的PCI设备的表格。
  • 搜索可启动的操作系统。实际上，根据BIOS的设置，该过程可能会尝试按照预定义的、可自定义顺序访问系统中每个软盘、硬盘和CD-ROM的第一个扇区（引导扇区）。
  • 一旦找到有效的设备，它就会将其第一个扇区的内容复制到RAM中，执行其中的代码（boot loader）。

Boot Loader

BIOS从某个存储设备的第一个扇区中加载到RAM中的程序就是boot loader,这个程序的作用，就是将kernel image 加载到RAM中。

如果BIOS找到的有效设备是硬盘，硬盘的第一个扇区叫做MBR(Master Boot Record ),其中包括 分区表和一个小程序。分区表中的每个表项通常包括某个分区的起始sector和终止sector，以及handle 这个分区的操作系统。小程序就是用来load the first sector of the partition containing the operating system to be started. Windows系统，只会加载有active 标志的分区，因此只有存储在active分区中的kernel image才会被加载。

linux 使用更复杂的boot loader替代这个小程序，可以使用户选择加载哪个操作系统。

80x86上常见的boot loader有LInux LOader (LILO)，the GRand Unified Bootloader (GRUB).这些boot loader可以识别磁盘中装了哪些操作提供，供用户选择加载。当用户选择好后，boot loader要么直接将其对应的分区的boot sector拷贝到RAM中并执行，要么直接将kernel image 拷贝到RAM中。

假设用户选择了加载linux系统，boot loader需要将 linux kernel image 加载到RAM中，其具体的步骤如下

  • Invokes a BIOS procedure to display a “Loading” message.
  • Invokes a BIOS procedure,将kernel image的前512bytes加载到RAM地址0x00090000处， 其中setup() function 的起始地址在0x00090200.
  • Invokes a BIOS procedure,将剩余的kernel image（被压缩）加载到 RAM中。 如果是小 image（compiled with make zImage）, 放到低地址0x00010000 处，如果是大image(compiled with make bzImage),放到高地址 0x00100000 处。In the following discussion, we say that the kernel image is “loaded low” or “loaded high” in RAM, respectively.
  • Jumps to the setup( ) code.

the setup( ) Function

setup()函数必须初始化计算机中的硬件设备并设置内核程序执行环境。尽管BIOS已经初始化了大多数硬件设备，但Linux不依赖它，而是以自己的方式重新初始化这些设备以增强可移植性和鲁棒性。 setup()主要执行以下操作：

  1. 调用BIOS例程，获取RAM的物理内存布局
  2. 设置键盘重复延迟和速率。（当用户按住某个键超过一定时间时，键盘设备会将相应的按键码反复发送到CPU。）
  3. 初始化视频适配器卡。
  4. 重新初始化磁盘控制器并确定硬盘参数。
  5. 检查IBM微通道总线（MCA）是否存在。 Checks for an IBM Micro Channel bus (MCA)
  6. 检查PS/2指针设备（总线鼠标）是否存在。 Checks for a PS/2 pointing device (bus mouse).
  7. 检查高级电源管理（APM）BIOS支持情况。Checks for Advanced Power Management (APM) BIOS support.
  8. 如果BIOS支持增强型磁盘驱动服务（Enhanced Disk Drive Services,EDD），则调用正确的BIOS procedure, 在RAM中构建一个表，描述系统中可用的硬盘。（该表中包含的信息可以通过读取sysfs特殊文件系统下firmware/edd目录中的文件来查看。）
  9. 如果内核映像被加载到RAM低端（物理地址0x00010000），则将其移动到物理地址0x00001000。相反，如果内核映像被加载到RAM高端，则不进行移动操作。这一步是必要的，因为内核映像是经过压缩处理的，解压例程需要一些空闲空间作为内存中内核映像后面的临时缓冲区。
  10. ......
  11. 设置临时中断描述符表（IDT）和临时全局描述符表（GDT）。Sets up a provisional Interrupt Descriptor Table (IDT) and a provisional Global Descriptor Table (GDT).
  12. Resets the floating-point unit (FPU), if any.
  13. 重新编程可编程中断控制器（PIC）以屏蔽所有中断，除了IRQ2，它是两个PIC之间级联中断。 Reprograms the Programmable Interrupt Controllers (PIC) to mask all interrupts, except IRQ2 which is the cascading interrupt between the two PICs.
  14. 通过在cr0状态寄存器中设置PE位来将CPU从实模式切换到保护模式。 cr0寄存器中PG位被cleared，因此分页仍然被禁用。
  15. 跳转到startup_32()汇编语言函数。

the startup_32( ) Functions

有两个不同的startup_32( )函数；我们在这里提到的是编码在arch/i386/boot/compressed/head.S文件中的函数。setup( )终止后，该函数已被移动到物理地址0x00100000或物理地址0x00001000，具体取决于内核映像是高位加载还是低位加载到RAM中。

这个函数的执行步骤如下：

  1. Initializes the segmentation registers and a provisional stack.
  2. Clears all bits in the eflags register。
  3. Fills the area of uninitialized data of the kernel identified by the _edata and _end symbols with zeros
  4. 调用 decompress_kernel() 函数来解压缩kernel image 。首先显示“Uncompressing Linux...”消息。在解压缩kernel image后，将显示“OK, booting the kernel.”消息。如果内核映像被低加载，则解压缩的内核放置在物理地址0x00100000处。否则，如果内核映像被高加载，则解压缩的内核放置在压缩image之后的临时缓冲区中。然后将已解压image移动到其最终位置，该位置从物理地址0x00100000开始。
  5. 跳转到物理地址0x00100000。

解压缩的kernel image 以 arch/i386/kernel/head.S 文件中包含的另一个 startup_32() 函数开头。为两个函数使用相同的名称不会有任何问题（除了让读者感到困惑），因为这两个函数都通过跳转到它们的初始物理地址来执行。

第二个 startup_32() 函数设置了第一个 Linux 进程（进程 0）的执行环境。该函数执行以下操作：

  1. 使用最终值初始化段寄存器。
  2. 用零填充内核的bss段。
  3. 初始化包含在swapper_pg_dir和pg0中的临时kernel Page Tables，将线性地址映射到相同的物理地址，如第2章“内核页表”中所述。
  4. 将Page Global Directory的地址存储在cr3寄存器中，并通过设置cr0寄存器中的PG位启用分页。
  5. 为进程0设置kernel mode stack。
  6. 再次清除eflags寄存器中所有位。
  7. 调用setup_idt()以使用空断点处理程序填充IDT（请参阅第4章“IDT的初步初始化”）。Invokes setup_idt( ) to fill the IDT with null interrupt handlers (see the section “Preliminary Initialization of the IDT” in Chapter 4).
  8. 将从BIOS获取的系统参数和传递给操作系统的参数放入第一个页面框架（请参阅第2章“物理内存布局”）。 Puts the system parameters obtained from the BIOS and the parameters passed to the operating system into the first page frame
  9. 确定处理器型号。
  10. 使用GDT和IDT表格地址加载gdtr和idtr寄存器。
  11. 跳转到start_kernel()函数。

the start_kernel( ) Function

start_kernel() 函数完成 Linux 内核的初始化。几乎每个内核组件都是由此函数初始化的；我们只提到其中一些：

  • 通过调用sched_init()函数（参见第7章），初始化调度程序。
  • 通过调用build_all_zonelists()函数（参见第8章中的“内存区域”部分）来初始化memory zones。
  • 通过调用page_alloc_init()和mem_init()函数（参见第8章中的“The Buddy System Algorithm”部分）来初始化Buddy system allocators。
  • 通过调用trap_init()(参见第4章中的“异常处理”部分)和init_IRQ()(参见第4章中的“IRO数据结构”部分)，执行IDT最终初始化。
  • 通过调用softirq_init()函数(参见第4章中的“Softirqs”部分)，初始化TASKLET_SOFTIRQ和HI_SOFTIRQ。
  • 时间日期由time_init()函数进行初始化(请参阅第6章“Linux时间保持架构”的相关内容)。
  • kmem_cache_init() 函数 (请查看 第8 章 “通用缓存与特定缓存”) 初始化了slab allocator
  • 调用calibrate_delay () 函数确定 the speed of the CPU clock(请查看 第6 章 “延迟功能”的相关内容)
  • 创建进程1 的内核线程，方法是使用kernel_thread () 函数。然后，该内核线程创建其他内核线程并执行/sbin/init程序，如在本书3.3节“Kernel Threads”所述。 The kernel thread for process 1 is created by invoking the kernel_thread( ) function. In turn, this kernel thread creates the other kernel threads and executes the /sbin/init program, as described in the section “Kernel Threads” in Chapter 3.

Besides the “Linux version 2.6.11...” message, which is displayed right after the beginning of start_kernel( ), many other messages are displayed in this last phase, both by the init program and by the kernel threads. At the end, the familiar login prompt appears on the console (or in the graphical screen, if the X Window System is launched at startup), telling the user that the Linux kernel is up and running.

简单总结 + 补充

  • 按下电源键，cpu reset 引脚raise,eip等寄存器设置指定值到ROM中的BIOS程序
  • BIOS程序运行
    • 检查硬件信息
    • 初始化硬件
    • 根据顺序检查启动设备，比如硬盘，软盘，u盘
    • 将启动设备的第一个扇区加载到RAM，其中存储boot loader程序
  • 如果是硬盘的第一个扇区被加载，其中包括分区表和boot loader程序。分区表存储硬盘不同分区的信息，不同的分区可以加载不同的操作系统。GRUB boot loader可以让用户选择加载哪个分区的操作系统，我们选择加载linux操作系统
  • 加载linux kernel image到指定的地址（0x00100000,1M内存地址处），跳转到setup程序地址处运行
  • 运行一系列setup程序，其主要步骤为
    • 检查并初始化硬件信息
    • 解压缩kernal image
    • 初始化内核页表，GDT,cpu切换到保护模式，地址翻译经过段单元和页单元的处理
    • 跳转到start_kernal函数
  • start_kernal初始化内核
    • 初始化进程管理，调度系统
    • 初始化内存管理，比如所有RAM page frame 描述符的初始化，内存分配系统的初始化
    • 中断系统的初始化
    • 日期，时间的初始化
    • 加载驱动程序
    • 创建内核线程，init进程
  • init进程会执行一系列的启动脚本，这些脚本负责启动各种系统服务，如网络服务、打印服务等
  • 启动图形界面：如果系统配置为使用图形界面，那么在启动过程的这一阶段，会启动X窗口系统和显示管理，如GDM、LightDM等。
  • 登录提示：如果是图形界面，显示管理会提供一个登录界面，用户可以输入用户名和密码进行登录。如果是命令行界面，login程序会直接被init启动。用户在命令行中输入用户名后，login程序会提示用户输入密码。
  • 登录验证： 无论是图形界面还是命令行，输入的密码都会被传递给PAM（Pluggable Authentication Modules）进行验证。PAM是一个框架，它允许系统管理员通过配置文件来选择不同的认证模块，以实现灵活的认证策略。
  • 会话启动：一旦用户通过验证，显示管理或login程序会为用户启动会话。在图形界面中，这通常意味着启动一个桌面环境，如GNOME、KDE、XFCE等。在命令行界面中，会启动一个shell，如bash、zsh等。
  • 用户环境：最后，用户的个人环境配置会被加载，如bashrc、profile等配置文件，用户便可以开始使用系统。
