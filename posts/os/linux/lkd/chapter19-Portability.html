chapter19-Portability

Word Size and Data Types

  • Word Size A word是处理器一次可以处理的数据量，以byte为单位。 当我们谈到多少位的机器时，这个多少位就代表了其word大小。比如inter i7 是64-bit chip,其word大小就是8bytes. 同时，这个大小也是处理器的通用寄存器的大小。数据线 的位数至少是word size,虚拟地址的位数应和word size一样大(虽然实际使用的，比如64位机子上，虚拟地址的位数可能小于64)。指针的位数等于word size,c type long 等于word size linux支持的每个架构都会在其文件中定义 BITS_PER_LONG 这个宏大小，其为c long type的位数，也就是word size.

  • Opaque Type 使用typedef 定义的类型，比如pid_t, atomic_t, dev_t, uid_t, gid_t

    • Do not assume the size of the type. It might be 32-bit on some systems and 64-bit on others. Moreover, kernel developers are free to change its size over time.
    • Do not convert the type back to a standard C type

  • Explicitly Sized Types linux kernel 在 中定义explicitly sized data types 以上这些类型只能在kernel 中使用，如果代码可能revealed to user-space,例如user-visible header file,则不能使用该类型。需要使用相应的带有前缀版的，比如u32.

  • Signedness of Chars c标准规定char 类型可以是signed,也可是unsigned.这是要由 compiler, processor or both to decide what the suitable default for the char type is. 大部分机子上，char 都是signed，范围为-128~127，也有不一样的，比如arm, char default to unsigned, range 0-255. 因此，当我们使用c char类型时，如果没有指明 signed or unsigned,则不能假设它到底为signed还是unsigned。 如果需要明确使用signed or unsigned,则需要加上相应的前缀，signed char, unsigned char

Data Alignment

数据对齐指的是数据在内存中存放的位置的规则。一个单独的变量，如果它的内存地址是其大小的整数倍，则我们说它是对齐的。比如如果某变量大小是2^n,则其存放地址的低n位应该是0，这样才是对齐的。 对于某些架构，对数据对齐与否要求很严格，比如 RISC-based, 如果加载的数据没有对齐，则会导致processor trap。其他系统，访问没有对齐的数据，虽然可行，但性能相比访问对齐的数据会下降。 如果需要写portable代码，则数据应该永远是对齐的。

  • Avoiding Alignment Issues 数据对齐的工作主要是compiler做的。不过如果上层程序员如果通过指针访问数据时，需要注意这个问题

    char wolf[] = “Like a wolf”;
char *p = &wolf[1];
unsigned long l = *(unsigned long *)p;

    这时，我们访问的这个地址可能就不是4字节或者8字节对齐的。

  • Alignment of Nonstandard Types

    • 数组的对齐就是对数组的数据类型的对齐，比如int型数组，其起始地址是4字节整数倍。这样，每个元素也是相应的倍数。
    • union类型的对齐是其中最大的元素的类型的对齐
    • The alignment of a structure is such that an array of the structure will have each element of the array properly aligned
  • Structure Padding Structures are padded so that each element of the structure is naturally aligned.This ensures that when the processor accesses a given element in the structure, that element is aligned. For example, consider this structure on a 32-bit machine:
    struct animal_struct {
  char dog; /* 1 byte */ 
  unsigned long cat; /* 4 bytes */
  unsigned short pig; /* 2 bytes */ 
  char fox; /* 1 byte */
}
    编译器在内存中创建该类型时，会加上一些padding
    struct animal_struct{
  char dog;
  u8 __pad0[3]; 
  unsigned long cat; 
  unsigned short pig; 
  char fox;
  u8 __pad1;
}
    第一个3字节的pad，是为了访问之后的cat时，地址是对齐的。最后的一个字节的pad，确保整个结构体的大小是4字节的整数倍，满足以上对齐要求的第三点. 如果这样安排结构体中的元素，则不需要padding
    struct animal_struct { 
  unsigned long cat;
  unsigned short pig; 
  char dog;
  char fox;
};

Byte Order

低位字节在低地址，小端字节序 高位字节在低地址，大端字节序 x86架构的为小端字节序，大部分其他架构的为大端字节序 比如对于数字1027，存储在4字节的int中，binary表示如下 00000000 00000000 00000100 00000011 

int x = 1;
if (*(char *)&x == 1) 
/* little endian */
else
/* big endian */

Time

The measurement of time is another kernel concept that can differ between architectures or even kernel revisions. Never assume the frequency of the timer interrupt or the number of jiffies per second. Instead, always use HZ to scale your units of time correctly.This is important because not only can the timer frequency differ among the various architectures, but it can also change on a given architecture from one kernel release to the next. For example,HZ is 100 on the x86 platforms.That is, the timer interrupt occurs 100 times per second, or every 10 milliseconds. Earlier in the 2.6 kernel series, however, HZ was 1000 on x86. On other architectures, the value differs: Alpha has HZ equal to 1024 and ARM has it equal to 100. Never simply compare jiffies to a number such as 100 and assume that always means the same thing.To scale time appropriately, multiply or divide by HZ. For example

HZ /* one second */ 
(2*HZ) /* two seconds */ 
(HZ/2) /* half a second */ 
(HZ/100) /* 10 ms */ 
(2*HZ/100) /* 20 ms */

Page Size

使用PAGE_SIZE这个宏表示一页的大小，而不是具体的数值。不同架构的page size不一样。 PAGE_SIZE单位是byte,The value PAGE_SHIFT is the number of bits to right-shift an address to derive its page number. 比如x86-32，PAGE_SIZE是4096，而PAGE_SHIFT是12

Processor Ordering

不同的架构，cpu保证的内存序也不一样。有的更严格，有的较为weak 如果我们在代码中使用内存序来保证并发访问的顺序，则应该假设cpu只提供最弱的内存序，代码中使用memory barrier.

SMP, Kernel Preemption, and High Memory

It might seem somewhat incorrect to include symmetrical multiprocessing, kernel preemption, and high memory in a discussion of portability. After all, these are not machine characteristics that affect an operating system, but instead they are features of the Linux kernel that are indeed somewhat architecture agnostic.They represent, however, important configuration options that you should always assume are available in your code.That is, always program for an SMP/preempt/highmem system and you will always be safe, in any configuration. In addition to the previous portability rules, you need to follow these as well:

  • Always assume your code will run on an SMP system and use appropriate locking.
  • Always assume your code will run with kernel preemption enabled and use appropriate locking and kernel preemption statements.
  • Always assume your code will run on a system with high memory (memory not permanently mapped) and use kmap() as needed.
