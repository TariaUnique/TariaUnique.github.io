经典的计算机系统架构

instruction cycle

硬件的核心是cpu中的控制单元，它按照cpu时钟信号的频率，循环执行以下的指令周期

  • 取指
  • 译码
  • 取操作数
  • 执行
  • 存储结果

ALU

cpu中的ALU(arithmetic and logic unit)单元负责算数和逻辑运算

System Bus

控制单元通过系统总线与内存，外设等其他硬件交互。系统总线主要分为3大类

  • 地址线
  • 数据线
  • 控制线

地址线就是负责传送地址的，数据线就是负责传统数据的，控制线，传送各种控制信号的，比如告知地址线或数据线上的数据有效的信号（ignals that tell when the information on the address and data buses is valid）

在控制单元的一个执行周期中，其与外设的交互，就是除了在译码器中译码，在ALU中计算之外的其他步骤了，包括取指，取操作数，存储结果，这些步骤，就是通过系统总线与其他硬件的交互完成的，这些交互总的来说分为2大类，bus read和bus write。

以ISA bus(Industry Standard Architecture)为例，ISA bus的时钟频率为8-10 MHz.

其bus read cycle为

  • 在第一个clock tick中，bus master,也就是cpu,会设置好地址线的信号，然后会pulses the BALE (Bus Address Latch Enable) signal to indicate that the address is valid.
  • 然后会设置MEMR (Memory Read) or IOR (Input/Output Read) signal，分别表示从内存读取或者从外设读取。
  • 最后等待4个clock tick,等 memory或者外设识别地址，将数据设置到数据线上。

其bus write cycle为

  • 在第一个clock tick中，bus master,也就是cpu,会设置好地址线的信号，然后会pulses the BALE (Bus Address Latch Enable) signal to indicate that the address is valid.同时会设置好数据线上的数据。
  • 然后会设置 MEMW (Memory Write) or IOW (Input/Output Write) signal，分别表示写入内存或写入外设。然后等待4个clock tick,用于内存或外设的写入。

我们通常讲cpu的主频，都是多少GHz,而这里ISA BUS的时钟频率只有8-10MHz,这里有着几百倍的速度差距。

Interrupt controller

为了能让外设能中断cpu的正常执行流，cpu还提供了INTR和INTK这两个信号。 在执行一个指令之前，控制单元会检查中断信号是否被设置，如果被设置，将会中断当前的执行流，设置指令寄存器到某个预定义的地址，然后回复INTK信号

而中断控制器，就是用来处理多个外设的中断的。The controller has several interrupt request inputs and takes care of aggregating those inputs into the interrupt request input of the processor using priorities and queuing and providing the processor with information to distinguish the interrupt requests.

插入一段关于中断，异常，trap, fault这些容易模糊的概念的总结

中断和异常的区别，在于中断是外设产生的，异步当前的指令执行流。而异常是在执行当前指令时产生的，比如指令的地址无效，操作数无效。

其处理步骤都是一样的，都是使用cpu提供的中断机制，每个外设的中断或指令执行异常对应的一个number，也就是一个处理过程。当cpu的中断引脚检测到中断信号被设置时，跳转到某个预定义的地址执行，该地址处的代码，就是根据中断号，从中断向量表中找到的对应的处理程序。

同时，异常主要分为以下两类，trap和fault. trap，比如系统调用，会陷入内核，执行系统调用处理，然后返回user mode继续执行后面的指令。而 fault,比如page fault,在处理完fault之后,会返回原先触发fault的指令再次执行。

不管是中断，异常，硬件中断，软件中断，trap,fault blabla这些一堆概念，其实都是同一个东西，使用cpu提供的中断机制，根据中断向量表，跳转到另一个执行流。

DMA

如果没有DMA,外设和内存之间的数据传递，就需要先读取到cpu中，在通过cpu将数据传到内存或外设。

有了DMA之后，外设和内存可以直接通过DMA传递数据，DMA负责对system bus设置地址，数据，信号，而不需要经过cpu. 这样cpu可以做自己的事，比如执行运算。这也是给cpu提供了一种指令执行的优化。

To provide means of transferring data without processor attention, the processor is equipped with the hold and hold acknowledge signals. The control unit of the processor checks whether the hold signal is set, and if it is, the control unit responds with setting the hold acknowledge signal and holding access to the processor bus until the hold signal is reset, effectively relinquishing control of the processor bus.

To better cope with situations where more devices can transfer data without processor attention, the handling of the hold signal is delegated to a direct memory access controller. The controller has several transfer request inputs associated with transfer counters and takes care of taking over the processor bus and setting the address and control signals during transfer.

Example: ISA Bus The ISA (Industry Standard Architecture) bus DMA cycle is commenced by the peripheral device requesting a transfer using one of the DRQ (DMA Request) signals. There are 4 or 8 DRQ signals, DRQ0 to DRQ3 or DRQ7, and 4 or 8 corresponding DACK (DMA Acknowledge) signals, DACK0 to DACK3 or DACK7, each associated with one set of transfer counters in the controller.

When the controller sees the peripheral device requesting a transfer, it asks the processor to relinquish the bus using the HRQ (Hold Request) signal. The processor answers with the HLDA (Hold Acknowledge) signal and relinquishes the bus. This typically happens at the end of a machine cycle.

Once the bus is not used by the processor, the controller performs the device-to-memory or memory-to-device bus transfer in a manner that is very similar to the normal processor-to-memory or memory-to-processor bus transfer. The controller sends the memory address on the address bus together with the AEN (Address Enable) signal to indicate that the address is valid, responds to the peripheral device requesting the transfer using one of the DACK signals, and juggles the MEMW and IOR or the MEMR and IOW signals to synchronize the transfer.

PS2:

ISA总线（Industry Standard Architecture bus）的操作速度范围，即ISA总线的时钟振荡器产生的周期性信号的频率在8到10兆赫兹（MHz）之间。时钟频率是衡量总线工作速度的一个指标，它决定了总线每秒可以进行多少次数据传输操作。

如果是数据传输速率，我们以6个时钟tick算一个时钟周期，而bus的宽度为16，也就是 16MBps - 20MBps / 6 = 2.6-3.3 MBps, 20-26 Mbps

由于ISA总线的协议和信号线上的操作，并不是每个时钟周期都能进行数据传输。例如，有些时钟周期用于控制信号的传输，有些可能用于数据的同步或者总线上的其他操作，实际的数据传输速率肯定要小于这个值，大约在8-16 Mbps之间

ISA总线会有时钟频率的原因是因为它是同步总线设计。在同步总线中，所有操作都是基于时钟信号来同步的。时钟信号提供了数据传输的节奏，确保了发送和接收设备之间的同步。每个时钟周期，数据可以在总线上移动一步。因此，时钟频率越高，理论上数据传输的速度就越快。

ISA总线最初是由IBM为其个人电脑设计的，它的时钟频率是相对较慢的，但足以满足当时的计算需求。随着技术的发展，ISA总线的速度逐渐成为系统性能的瓶颈，因此它被更快速的总线标准，如PCI总线所取代。

PCI（Peripheral Component Interconnect）总线是高速串行总线标准，用于连接各种外围设备与中央处理器（CPU）。根据不同的PCI版本，其数据传输速率也有所不同。

PCI Express（PCIe）：这是最新的PCI总线标准，具有非常高的数据传输速率。PCIe 3.0的理论峰值数据传输速率可以达到每秒12GB/s（单向），而PCIe 4.0则进一步提升到每秒16GB/s。实际的数据传输速率会受到多种因素的影响，包括总线宽度、时钟频率以及数据块大小等。

PCI总线的数据传输速率取决于具体的总线标准和版本。最新版本的PCI Express（PCIe）拥有最高的数据传输速率，能够满足现代计算机系统中对于高速数据传输的需求。
