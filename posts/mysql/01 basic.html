01 basic

primary key

  • A Primary Key is a field (or a combination of fields) that uniquely identifies each record in a table.
  • A table can have only one Primary Key.
  • The values in a Primary Key must be unique and not null.
  • By default, MySQL automatically creates a unique index for the Primary Key.
    CREATE TABLE students (
  student_id INT PRIMARY KEY,
  name VARCHAR(100)
);

unique key

  • A Unique Key is a constraint that ensures all values in a column (or a combination of columns) are unique across the table.
  • Unlike the Primary Key, a table can have multiple Unique Keys.
  • A Unique Key allows NULL values (but a column with a unique constraint can only have one NULL value ).
    CREATE TABLE employees (
  employee_id INT PRIMARY KEY,
  email VARCHAR(100) UNIQUE,
  name VARCHAR(100)
);

foreign key

  • A Foreign Key is a field (or a combination of fields) in one table that uniquely identifies a row of another table.
  • It establishes a relationship between two tables and ensures referential integrity, meaning the foreign key value must exist in the referenced table’s primary key or unique key column.
  • A Foreign Key constraint prevents the insertion of a record with a value that doesn’t exist in the referenced table.
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);

  • one to one A one-to-one relationship means that each row in the first table can be linked to only one row in the second table, and vice versa.

    CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    name VARCHAR(100)
);

CREATE TABLE passports (
    passport_id INT PRIMARY KEY,
    employee_id INT UNIQUE,  -- Unique foreign key referencing employee
    passport_number VARCHAR(20),
    FOREIGN KEY (employee_id) REFERENCES employees(employee_id)
);
    • The employees table has a primary key (employee_id).
    • The passports table has a unique foreign key (employee_id), which ensures that each passport is linked to only one employee and vice versa.

  • one to many

    • A one-to-many relationship means that one row in the first table can be linked to multiple rows in the second table, but each row in the second table can be linked to only one row in the first table.
    • This is the most common relationship in relational databases. The "many" side will have a foreign key that references the "one" side. ```sql CREATE TABLE customers ( customer_id INT PRIMARY KEY, name VARCHAR(100) );

    CREATE TABLE orders (

    order_id INT PRIMARY KEY,
customer_id INT,  -- Foreign key referencing customer
order_date DATE,
FOREIGN KEY (customer_id) REFERENCES customers(customer_id)

    ); ```

  • many to many

    • A many-to-many relationship means that multiple rows in the first table can be linked to multiple rows in the second table.
    • This relationship is implemented using an intermediate (junction) table that holds foreign keys to both tables involved in the relationship. Each foreign key corresponds to a primary key in the related table ```sql CREATE TABLE students ( student_id INT PRIMARY KEY, name VARCHAR(100) );

    CREATE TABLE courses (

    course_id INT PRIMARY KEY,
course_name VARCHAR(100)

    );

    CREATE TABLE student_courses (

    student_id INT,
course_id INT,
PRIMARY KEY (student_id, course_id),
FOREIGN KEY (student_id) REFERENCES students(student_id),
FOREIGN KEY (course_id) REFERENCES courses(course_id)

    ); ```

left outer join return all the rows from left table with the matching rows from the right table. if there is no matching rows in right table, it returns null value. same as right outer join

select t1.id as t1id,t1.name as t1name ,t2.id as t2id,t2.name as t2name

select t1.id as t1id,t1.name as t1name ,t2.id as t2id,t2.name as t2name from table2 t2 left join table1 t1 on t1.id=t2.id

  • a view is commonly known as a virtual table
  • a view is a virutal table based on the result set of the sql statement
  • a view consists of a select statement that is stored as an object in the database
  • the tables referenced in the views are known as base table
  • technically views does not store any data. the data are retireved at run time from the base table
  • mysql support nested view --- a view that is based on another view
  • mysql does not support materialized view(view itself stores data)

  • create: This keyword is used to create a new view.
  • or replace: If specified, it allows the view to be replaced if it already exists. This is useful for updating the definition of an existing view without having to drop it first.
  • [algorithm= {undefined | merge | temptable}]:
    • ALGORITHM: This optional clause specifies the algorithm used for the view.
    • UNDEFINED: The database system chooses the algorithm automatically.
    • MERGE: The view's query is merged with the outer query that uses the view.
    • TEMPTABLE: The view's result set is stored in a temporary table before applying the outer query. 比如我们有如下表
      CREATE TABLE employees (
id INT PRIMARY KEY,
name VARCHAR(100),
department_id INT,
salary DECIMAL(10, 2)
)
      我们创建了一个view,算法是merge
      CREATE ALGORITHM = merge VIEW high_earners AS
SELECT id, name, department_id, salary
FROM employees
WHERE salary > 50000;
      现在我们在这个view上查询
      SELECT * FROM high_earners WHERE department_id = 3;
      If the merge algorithm is not used,temptable也就是这种情况 ，the database might first execute the view's query to create a temporary result set of all employees with a salary greater than $50,000, and then filter this result set by department_id = 3. With the merge algorithm, the database combines the view's query with the outer query. This means the database rewrites the query to:
      SELECT id, name, department_id, salary
FROM employees
WHERE salary > 50000 AND department_id = 3;
      By merging the view's query with the outer query, the database can optimize the execution plan more effectively. It doesn't need to create a temporary result set of all high earners first; instead, it directly filters the employees table for rows that meet both conditions (salary > 50000 and department_id = 3).
  • [definer = {user | current_user}] : view的定义者，默认是current_user
  • [sql security {definer | invoker}]
    • SQL SECURITY: This optional clause specifies whether the view is executed with the privileges of the user who defined it or the user who invokes it.
    • DEFINER: The view is executed with the privileges of the user who defined it.
    • INVOKER: The view is executed with the privileges of the user who invokes it.
  • view view_name [{column_list}]
    • VIEW view_name: Specifies the name of the view.
    • (column_list): An optional list of column names for the view. If not specified, the column names are derived from the select_statement.
  • [WITH [CASCADED | LOCAL] CHECK OPTION]:
    • WITH CHECK OPTION: This optional clause ensures that rows inserted or updated through the view satisfy the view's SELECT statement.
    • CASCADED: Ensures that the CHECK OPTION applies to all underlying views.
    • LOCAL: Ensures that the CHECK OPTION applies only to the immediate view.

triggers a trigger is a database object that is automatically executed or fired when certain events occur on a particular table. Triggers can be used to enforce business rules, validate input data, maintain audit trails, and more. They are associated with a table and are triggered by events such as INSERT, UPDATE, or DELETE.

CREATE TRIGGER before_insert_example
BEFORE INSERT ON your_table_name
FOR EACH ROW
BEGIN
    -- Your trigger logic here
    SET NEW.column_name = 'default_value';
END;
  • BEFORE INSERT specifies that the trigger should fire before an INSERT operation.
  • FOR EACH ROW indicates that the trigger will execute for each row inserted. MySQL only support row-level triggers.
  • SET NEW.column_name = 'default_value' statement is used to modify the value of a column in the row that is being inserted or updated. NEW is a keyword that refers to the new row data that is being inserted or updated. It is available in BEFORE INSERT, AFTER INSERT, BEFORE UPDATE, and AFTER UPDATE triggers.

In MySQL, triggers can be defined for the following events:

  • BEFORE INSERT: Executes before a new row is inserted into a table.
  • AFTER INSERT: Executes after a new row has been inserted into a table.
  • BEFORE UPDATE: Executes before an existing row is updated in a table.
  • AFTER UPDATE: Executes after an existing row has been updated in a table.
  • BEFORE DELETE: Executes before a row is deleted from a table.
  • AFTER DELETE: Executes after a row has been deleted from a table.

Example: Audit Log for Inserts

CREATE TABLE audit_log (
    id INT AUTO_INCREMENT PRIMARY KEY,
    action VARCHAR(50),
    table_name VARCHAR(50),
    timestamp DATETIME,
    details TEXT
);

CREATE TRIGGER after_insert_log
AFTER INSERT ON your_table_name
FOR EACH ROW
BEGIN
    INSERT INTO audit_log (action, table_name, timestamp, details)
    VALUES ('INSERT', 'your_table_name', NOW(), CONCAT('Inserted row with ID: ', NEW.id));
END;

Automatically Update a Timestamp

CREATE TRIGGER before_update_timestamp
BEFORE UPDATE ON your_table_name
FOR EACH ROW
BEGIN
    SET NEW.last_modified = NOW();
END;

CREATE TRIGGER before_delete_check

    IF OLD.status = 'protected' THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Cannot delete protected rows';

CREATE TABLE sales_summary (

CREATE TRIGGER after_insert_sales

Events Events allows you to schedule and automate tasks to run at specified times or intervals directly within the database server. Similar to cron jobs in Unix/Linux systems or scheduled tasks in Windows, MySQL events enable you to execute SQL statements automatically without manual intervention or external scripting.

Before creating events, ensure that the Event Scheduler is active:

-- Check the status of the Event Scheduler
SHOW VARIABLES LIKE 'event_scheduler';

-- Enable the Event Scheduler
SET GLOBAL event_scheduler = ON;

create event

CREATE EVENT [IF NOT EXISTS] event_name
ON SCHEDULE schedule
[ON COMPLETION [NOT] PRESERVE]
[ENABLE | DISABLE]
[COMMENT 'comment']
DO
sql_statement;
  • event_name: A unique identifier for the event.
  • ON SCHEDULE: Defines when and how often the event runs.
  • ON COMPLETION: Determines whether the event is dropped after it finishes (for one-time events).
  • ENABLE | DISABLE: Sets the event's initial state.
  • sql_statement: The SQL command(s) to execute.

Scheduling Options

  • One-Time Execution: 
    ON SCHEDULE AT 'yyyy-mm-dd hh:mm:ss'
  • Recurring Execution:
    ON SCHEDULE EVERY interval [STARTS timestamp] [ENDS timestamp]
    • EVERY interval: Specifies the frequency (e.g., EVERY 1 DAY).
    • STARTS timestamp: (Optional) When the event begins.
    • ENDS timestamp: (Optional) When the event stops.
    • Interval Examples:
      • SECOND, MINUTE, HOUR, DAY, WEEK, MONTH, YEAR
      • Combine intervals, e.g., EVERY 2 WEEK.

Example: Suppose you have a table logs and want to delete records older than 30 days every night at midnight:

CREATE EVENT IF NOT EXISTS cleanup_logs
ON SCHEDULE EVERY 1 DAY
STARTS CURRENT_DATE + INTERVAL 1 DAY
DO
  DELETE FROM logs WHERE log_date < NOW() - INTERVAL 30 DAY;

Managing Events

  • View Existing Events:

    -- Show all events in the current database
SHOW EVENTS;

-- Show detailed information
SELECT * FROM information_schema.EVENTS WHERE EVENT_SCHEMA = 'your_database_name';
  • Modifying an Event:
    ALTER EVENT event_name
ON SCHEDULE EVERY 1 WEEK
DO
  -- New or modified SQL statement
  • Removing an Event:
    DROP EVENT [IF EXISTS] event_name;

Important Considerations

  • Database Scope: Events are associated with a specific database. Ensure you're using the correct database context.
  • Privileges: You need the EVENT privilege to create, alter, or drop events.
  • Event Scheduler Status: Events won't run if the Event Scheduler is disabled.
  • Server Restart: Event Scheduler settings may reset after a server restart unless configured in the MySQL configuration file (my.cnf or my.ini).

Use Cases for MySQL Events

  • Maintenance Tasks: Automate backups, optimize tables, or update statistics.
  • Data Management: Purge old data, aggregate data into summary tables.
  • Notifications: Generate reports or alerts based on scheduled queries.
  • Synchronization: Refresh materialized views or sync data between tables.

Conclusion MySQL events provide a powerful way to automate tasks within the database, reducing the need for external scripts or manual intervention. By leveraging events, you can streamline database operations, improve efficiency, and ensure critical tasks run reliably on schedule.
