07 epoll

epoll是Linux特有的I/O多路复用机制，它在性能上有显著优势，尤其是在处理大量文件描述符时。 epoll通过epoll_create创建一个epoll实例，然后使用epoll_ctl添加、修改或删除需要监视的文件描述符。 epoll_wait用于等待文件描述符的I/O事件，它返回就绪的文件描述符列表，而不需要像select和poll那样每次调用都传递所有文件描述符。

epoll在处理大量的文件描述符时效率比select，poll要高

  • select,poll在调用接口时都需要传递监听描述符的数组作为参数，而epoll是内核维持需要监听的描述符的相关数据，事先将需要监听的描述符和相关event等数据注册到内核维持的数据结构即可，在调用接口时避免了大量数据的拷贝的开销
  • 每次在调佣select(),或者poll()时,内核都需要iterate through all watched file descriptors, making it O(n) complexity.
  • epoll的设计，使得我们在调用epoll_wait()时，内核不需要检查每一个监听的描述符的状态，而只需要返回已经有事件发生的描述符的ready list即可，其复杂度是O(1)

epoll的原理 我们调用epoll_create()创建一个epoll instance时，内核会创建一个event poll(struct eventpoll),代表这个epoll instance, 这个event poll中主要有两个数据结构，一个是Event Poll Item (struct epitem)的红黑树，一个是Event Poll Item (struct epitem)的链表。

Event Poll Item (struct epitem): For every file descriptor that gets added to the epoll instance using epoll_ctl(), the kernel creates an epitem. This structure holds information about the file descriptor, the events of interest, and a pointer to the owning eventpoll structure.

Each epitem is attached to the file descriptor’s (socket file) inode structure in the kernel. When an event occurs on a file descriptor, the kernel immediately knows which epitems are associated with it, and can therefore quickly find all epoll instances that are interested in this event. 并且将对应的epitem加入到ready list中

The kernel maintains a red-black tree for every eventpoll structure to keep track of all its epitems. This allows the kernel to efficiently look up an epitem when a file descriptor is modified or deleted.

When epoll_wait() is called, the kernel checks the list of ready file descriptors in the eventpoll structure. If this list is not empty, these ready file descriptors are returned to the caller. If the list is empty, the caller is put to sleep until an event occurs or the timeout expires.

when an I/O event happens on a socket or any other file descriptor registered with epoll, a hardware interrupt is generated by the device (for example, a network card in case of a socket). This interrupt causes the CPU to stop what it's doing and transfer control to a specific location in memory (an interrupt handler). This is often referred to as "trapping into the kernel".

The interrupt handler, part of the kernel's code, then determines the cause of the interrupt and processes it. If the interrupt was due to an I/O event on a file descriptor that's being monitored by epoll(there are epitem pointers in its inode structure),the kernel will add the corresponding epitem to the epoll instance's ready list

epoll的使用

/*
this function creates an epoll instance and returns a file descriptor referring to that instance. There are two possible flags that can be passed:
* EPOLL_CLOEXEC: Set the close-on-exec (FD_CLOEXEC) flag on the new file descriptor. 
* 0: If this flag is set as 0, it means no flags are set.
*/
int epoll_create1 (int flags);

/* Manipulate an epoll instance "epfd". Returns 0 in case of success,
   -1 in case of error ( the "errno" variable will contain the
   specific error code ) The "op" parameter is one of the EPOLL_CTL_*
   constants defined above. The "fd" parameter is the target of the
   operation. The "event" parameter describes which events the caller
   is interested in and any associated user data.  */
    int epoll_ctl (int __epfd, int __op, int __fd,
              struct epoll_event *__event)

/* Valid opcodes ( "op" parameter ) to issue to epoll_ctl().  */
#define EPOLL_CTL_ADD 1    /* Add a file descriptor to the interface.  */
#define EPOLL_CTL_DEL 2    /* Remove a file descriptor from the interface.  */
#define EPOLL_CTL_MOD 3    /* Change file descriptor epoll_event structure.  */


/* Wait for events on an epoll instance "epfd". Returns the number of
   triggered events returned in "events" buffer. Or -1 in case of
   error with the "errno" variable set to the specific error code. The
   "events" parameter is a buffer that will contain triggered
   events. The "maxevents" is the maximum number of events to be
   returned ( usually size of "events" ). The "timeout" parameter
   specifies the maximum wait time in milliseconds (-1 == infinite).
 */
extern int epoll_wait (int __epfd, struct epoll_event *__events,
               int __maxevents, int __timeout);



typedef union epoll_data

struct epoll_event

epoll支持边缘触发（ET）和水平触发（LT）两种模式,默认的socket都是水平触发。select和poll只有水平触发模式。

水平触发：当文件描述符就绪时，epoll会通知处理程序。如果程序没有处理完该文件描述符上的所有数据，那么在随后的调用中，epoll会再次通知。在水平触发模式下，即使某个文件描述符已经就绪，如果没有处理完，epoll会不断触发通知，直到该文件描述处理完为止。这种模式编程相对简单，因为不需要担心什么时候处理完所有数据，epoll会不断提醒你，直到你处理完毕。

边缘触发（Edge Triggered）：当文件描述符的状态发生变化时，epoll会通知处理程序。但是，处理程序必须处理完所有就绪的文件描述符，因为除非文件描述符的状态再次发生变化，否则epoll不会再发出通知。边缘触发模式下，epoll的通知更少，因为它只在文件描述符状态变化时通知，而不是像水平触发那样，只要文件描述符就绪就会通知。 这种模式可以提供更高的性能，因为它减少了epoll的通知次数，但是编程也相对复杂，因为需要确保在每次通知时都处理完所有就绪的文件描述符。

一个简单的使用epoll的tcp服务器

#include <iostream>
#include <netinet/in.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/epoll.h>
#include <string.h>

#define MAX_EVENTS 10

int set_nonblocking(int sockfd) {
    int flags = fcntl(sockfd, F_GETFL, 0);
    if (flags == -1) {
        std::cerr << "Failed to get socket flags" << std::endl;
        return -1;
    }
    flags |= O_NONBLOCK;
    if (fcntl(sockfd, F_SETFL, flags) == -1) {
        std::cerr << "Failed to set socket as non-blocking" << std::endl;
        return -1;
    }
    return 0;
}

int main() {
    int server_fd, epoll_fd;
    struct sockaddr_in address;
    int opt = 1;
    struct epoll_event event, events[MAX_EVENTS];

    // Create a file descriptor for the server socket
    if ((server_fd = socket(AF_INET, SOCK_STREAM, 0)) == 0) {
        perror("socket failed");
        exit(EXIT_FAILURE);
    }


    if (setsockopt(server_fd, SOL_SOCKET, SO_REUSEADDR | SO_REUSEPORT, &opt, sizeof(opt))) {
        perror("setsockopt");
        exit(EXIT_FAILURE);
    }
    address.sin_family = AF_INET;
    address.sin_addr.s_addr = INADDR_ANY;
    address.sin_port = htons(8080);

    // Bind the socket to the address and port
    if (bind(server_fd, (struct sockaddr *)&address, sizeof(address)) < 0) {
        perror("bind failed");
        exit(EXIT_FAILURE);
    }

    // Listen for incoming connections
    if (listen(server_fd, 3) < 0) {
        perror("listen");
        exit(EXIT_FAILURE);
    }

    // Set the socket as non-blocking
    if (set_nonblocking(server_fd) == -1) {
        exit(EXIT_FAILURE);
    }

    // Create an epoll instance
    epoll_fd = epoll_create1(0);
    if (epoll_fd == -1) {
        perror("epoll_create1");
        exit(EXIT_FAILURE);
    }

    event.data.fd = server_fd;
    event.events = EPOLLIN;
    if (epoll_ctl(epoll_fd, EPOLL_CTL_ADD, server_fd, &event) == -1) {
        perror("epoll_ctl");
        exit(EXIT_FAILURE);
    }

    while (true) {
        int n = epoll_wait(epoll_fd, events, MAX_EVENTS, -1);
        for (int i = 0; i < n; i++) {
            if (events[i].events & EPOLLERR || events[i].events & EPOLLHUP ||events[i].events & EPOLLRDHUP ) {
                close(events[i].data.fd);
                if (epoll_ctl(epoll_fd, EPOLL_CTL_DEL, events[i].data.fd, NULL) == -1) {
                    perror("epoll_ctl");
                    exit(EXIT_FAILURE);
                }
            } else if (events[i].events & EPOLLIN &&  server_fd == events[i].data.fd) {
                // A new connection is incoming; accept it
                while (true) {
                    struct sockaddr_in client_address;
                    socklen_t client_address_len = sizeof(client_address);
                    int client_fd = accept(server_fd, (struct sockaddr *)&client_address, &client_address_len);
                    if (client_fd == -1) {
                        break;
                    }
                    if (set_nonblocking(client_fd) == -1) {
                        exit(EXIT_FAILURE);
                    }
                    event.data.fd = client_fd;
                    event.events = EPOLLIN;
                    if (epoll_ctl(epoll_fd, EPOLL_CTL_ADD, client_fd, &event) == -1) {
                        perror("epoll_ctl");
                        exit(EXIT_FAILURE);
                    }
                }
            } else if (events[i].events & EPOLLIN){
                // Data is available to read
                char buffer[1024] = {0};
                ssize_t count = read(events[i].data.fd, buffer, sizeof(buffer));
                if (count == -1) {
                    // Read error
                    perror("read");
                    continue;
                }
                if (count == 0) {
                    // Connection closed by the client
                    close(events[i].data.fd);
                    if (epoll_ctl(epoll_fd, EPOLL_CTL_DEL, events[i].data.fd, NULL) == -1) {
                        perror("epoll_ctl");
                        exit(EXIT_FAILURE);
                    }
                    continue;
                }
                // Process the data and send a response
                std::cout << "Received data: " << buffer << std::endl;
                write(events[i].data.fd, buffer,count);
            }
        }
    }

    close(server_fd);
    return 0;
}

我们使用setsockopt给listen socket设置了SO_REUSEADDR 和SO_REUSEPORT 选项

SO_REUSEADDR：这个选项告诉操作系统，如果这个端口上已经有绑定过的套接字，但是这些套接字处于TIME_WAIT状态，那么仍然允许新的套接字绑定到这个端口上。TIME_WAIT状态是TCP连接关闭后的一种状态，它确保远端的TCP连接有足够的时间收到最后一个ACK包。如果没有设置SO_REUSEADDR，尝试绑定到一个处于TIME_WAIT状态的端口将会失败。 SO_REUSEPORT：这个选项允许多个套接字绑定到同一个端口，只要这些套接字的绑定地址相同。这对于多进程或多线程服务器很有用，因为它允许多个套接字监听同一个端口，从而提高服务器的性能和可伸缩性。每个套接字可以由不同的进程或线程处理，这样负载就可以分散到多个处理器核心上。

setsocketopt

int setsockopt(int sockfd, int level, int optname, const void *optval, socklen_t optlen);

sockfd：指向一个打开的套接字的文件描述符。 level：指定选项所在的协议级别。对于套接字级别选项，这个参数设置为SOL_SOCKET。 optname：指定要设置的选项的名称，例如SO_REUSEADDR、SO_REUSEPORT等。 optval：指向一个变量的指针，该变量包含了选项的值。 optlen：指定optval所指变量的长度。

成功时，返回0。

失败时，返回-1，并设置errno来表示错误原因。

其中，level参数用于指定套接字选项的协议级别，它可以设置以下几个值： SOL_SOCKET：表示套接字级别选项，这些选项适用于所有套接字协议。 IPPROTO_IP：用于IPv4套接字的选项。 IPPROTO_IPV6：用于IPv6套接字的选项。 IPPROTO_TCP：用于TCP套接字的选项。 IPPROTO_UDP：用于UDP套接字的选项。 其他协议级别：对于其他协议，level参数可以是特定协议的协议编号，例如IPPROTO_ICMP用于ICMP协议。 在不同的协议级别下，可以设置的选项是不同的。例如，SO_REUSEADDR和SO_REUSEPORT是套接字级别的选项，因此在使用这些选项时，level参数应该设置为SOL_SOCKET。而如果你想要设置TCP级别的选项，比如TCP_NODELAY，那么level参数应该设置为IPPROTO_TCP。
