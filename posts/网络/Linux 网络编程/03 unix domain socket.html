03 unix domain socket

UNIX域套接字（Unix Domain Sockets，简称UDS）是一种在UNIX和类UNIX操作系统中用于进程间通信（IPC）的机制。它们允许在同一台主机上的进程间通过文件系统中的特殊文件（称为套接字文件）进行数据交换。UNIX域套接字提供了两种通信方式：流式（SOCK_STREAM）和数据报式（SOCK_DGRAM），类似于网络套接字的TCP和UDP通信。

流式套接字（SOCK_STREAM）：提供有序、可靠、双向的通信方式，类似于TCP通信。 数据报套接字（SOCK_DGRAM）：提供无连接、不可靠、数据报形式的通信方式，类似于UDP。

UNIX域套接字相比网络套接字有一些优势，不需要经过网络协议栈，因此有更高的通信效率，速度更快。同时，由于它们不通过网络传输，因此比网络套接字更安全。此外，UNIX域套接字在权限和安全方面提供了细粒度的控制，可以通过文件系统的权限设置来限制对套接字的访问。

套接字创建：

  • 进程通过socket()系统调用请求内核创建一个套接字。
  • 内核为该套接字分配必要的资源，并在内核空间中创建一个套接字数据结构。 绑定地址：
  • 进程通过bind()系统调用将套接字与一个文件系统中的路径名（套接字文件）关联起来。
  • 内核记录这个路径名，并将其与套接字数据结构关联。 监听和连接（对于流式套接字）：
  • 服务器进程通过listen()系统调用通知内核它愿意接受连接。
  • 内核将套接字状态设置为监听状态，并准备接受连接请求。
  • 客户端进程通过connect()系统调用请求与服务器进程的套接字建立连接。
  • 内核检查服务器套接字的状态，并在两者之间建立连接。 数据传输：
  • 发送进程通过send()、write()等系统调用将数据写入套接字。
  • 内核将数据从用户空间复制到内核空间的套接字发送缓冲区。
  • 对于流式套接字，内核确保数据的顺序和可靠性。
  • 内核检查对方套接字的接受缓冲区空间，并将数据复制过去。
  • 接收进程通过recv()、read()等系统调用从套接字读取数据。
  • 内核将数据从内核空间的接收缓冲区复制到用户空间的进程缓冲区。 结束通信：
  • 任何一方或双方可以通过close()系统调用关闭套接字，内核释放与该套接字相关的资源。
  • 对于流式套接字，如果服务器端或客户端关闭了套接字，另一端的进程也会收到一个文件结束（EOF）的指示。（read/recv返回空数据）

当我们创建unix域套接字时，内核会为套接字分配的资源有

  • 套接字相关的结构，比如struct socket，这是内核中用于表示套接字的主要数据结构。它包含了套接字的各种信息，如套接字类型（流式或数据报）、状态、引用计数、发送和接收缓冲区等。struct sockaddr_un，这个结构用于存储套接字的地址信息，包括地址家族（AF_UNIX）和套接字文件的路径名。
  • 跟套接字文件相关的数据结构：比如inode（存储该套接字文件的元信息，权限、大小、创建时间），dentry（存储套接字的路径信息），这些数据结构只存在于内存中，不占用磁盘空间。
  • 跟打开文件相关的数据结构，用户空间是返回的文件描述符，内核空间有文件表项（struct file，包含当前读写指针偏移量、访问模式（读、写、读写）、文件状态标志，指向的inode等），文件操作结构（struct file_operations 这个结构体定义了一组函数指针，用于实现文件的各种操作，如读、写、打开、关闭等。每个struct file都会指向一个适当的struct file_operations，以支持对应的文件类型（普通文件、套接字、设备文件等）的操作），文件描述符表（它是一个数组，每个元素都是一个指向struct file的指针。当进程进行系统调用（如read()、write()）时，它会指定一个文件描述符，内核会根据这个文件描述符在文件描述符表中查找对应的struct file，然后执行相应的操作。）
  • 发送和接收缓冲区：内核为每个套接字分配了发送缓冲区和接收缓冲区。这些缓冲区用于暂存发送和接收的数据，直到数据可以被处理或传输。
  • 套接字队列：对于流式套接字，内核维护了两个队列：一个用于未完成连接的请求队列（SYN队列），另一个用于已完成的连接队列。这些队列用于管理多个客户端与服务器之间的连接。
  • 引用计数：内核维护了一个引用计数来跟踪有多少进程在使用这个套接字。当最后一个引用被释放时，内核会清理套接字的资源。
  • 协议特定资源：根据套接字的协议（流式或数据报），内核可能会分配额外的资源来支持特定的通信语义，如数据包的顺序和可靠性。 这些资源在套接字的整个生命周期中被创建、使用和维护。当套接字被关闭时，内核会释放这些资源，以避免内存泄漏和其他资源浪费。UNIX域套接字的这些内核资源共同工作，提供了高效、可靠的进程间通信机制。

UNIX域套接字也可以有阻塞和非阻塞两种模式。这与其他类型的套接字（如网络套接字）的阻塞和非阻塞模式类似。 阻塞模式： 在阻塞模式下，当发起一个可能会阻塞的操作（如connect()、accept()、read()或write()）时，调用线程会被阻塞，直到操作完成或发生错误。 如果服务器套接字在阻塞模式下监听连接，那么accept()调用会在没有新连接到达时阻塞。 如果一个阻塞模式的套接字尝试读取数据，但数据尚未到达，那么read()调用会阻塞，直到有数据可读或发生错误，或者连接关闭。同样，如果一个阻塞模式的套接字尝试写入数据，但缓冲区已满，那么write()调用会阻塞，直到缓冲区有空间可写或发生错误 非阻塞模式： 在非阻塞模式下，套接字操作会立即返回，即使操作不能立即完成。 如果非阻塞模式的connect()调用未能立即建立连接，它会返回一个错误（EINPROGRESS）。 非阻塞模式的read()和write()调用也会立即返回。如果操作不能立即完成，这些调用会返回一个错误，指示操作会阻塞（例如，EAGAIN或EWOULDBLOCK）。 在非阻塞模式下需要与事件通知机制（如select、poll、epoll）一起使用来检查套接字的状态，以确定何时可以执行操作。非阻塞模式和时间通知机制一起使用，提供了一种在单个线程中管理多个套接字的方法，这对于实现高并发的应用程序非常有用。

在python的socket库中，使用UNIX域套接字的方法和网络套接字基本一样，需要处理的异常情况也是一样的，重点是在非阻塞socket的方法中，我们需要关注error number等于EWOULDBLOCK,EAGAIN,EINPROGRESS的error即可。参考网络socket各个接口的异常处理。

UNIX域套接字与网络套接字的区别

  • UNIX域套接字不通过网络协议栈，它们直接在进程之间传输数据，因此速度更快。
  • UNIX域套接字使用文件系统中的路径名作为地址，而不是IP地址和端口号。
  • UNIX域套接字可以利用文件系统的权限和访问控制来限制对套接字的访问，提供了一种安全机制。
  • UNIX域套接字在许多UNIX和Linux系统服务中广泛使用，例如，它们用于在shell和它启动的进程之间、本地服务进程和客户端之间、以及系统守护进程和系统服务之间的通信。

以下是一个使用Python3的socket库实现的UNIX域流式套接字的客户端和服务器端示例代码。这个例子展示了如何使用非阻塞模式的套接字配合select模块来进行通信。

首先是服务器端代码

import socket
import select

# 定义套接字文件路径和缓冲区大小
UNIX_SOCKET_PATH = '/tmp/uds_socket'

# 创建UNIX域套接字
server_socket = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)

# 绑定套接字到地址
server_socket.bind(UNIX_SOCKET_PATH)

# 监听套接字
server_socket.listen()

# 设置为非阻塞模式
server_socket.setblocking(False)

# 准备select的输入集合
inputs = [server_socket]

print(f"Server is listening on {UNIX_SOCKET_PATH}")

while inputs:
    # 使用select进行IO多路复用
    readable, writable, exceptional = select.select(inputs, [], [])

    for s in readable:
        if s is server_socket:
            # 接受客户端连接
            client_socket, client_address = server_socket.accept()
            print(f"Client connected from {client_address}")
            client_socket.setblocking(False)
            inputs.append(client_socket)
        else:
            # 读取客户端发送的数据
            try:
                data = s.recv(1024)
                if data:
                    print(f"Received data: {data.decode()}")
                    # 回显数据到客户端
                    s.sendall(data)
                else:
                    # 客户端关闭连接
                    print("Client disconnected")
                    s.close()
                    inputs.remove(s)
            except socket.error as e:
                # 处理非阻塞套接字可能出现的异常
                print(f"Error receiving data: {e}")
                s.close()
                inputs.remove(s)

# 关闭服务器端的套接字
server_socket.close()

# 删除UNIX域套接字文件
unlink(UNIX_SOCKET_PATH)

import socket
import select

UNIX_SOCKET_PATH = '/tmp/uds_socket'


# 创建UNIX域套接字
client_socket = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)

# 连接到服务器
client_socket.connect(UNIX_SOCKET_PATH)

# 设置为非阻塞模式
client_socket.setblocking(False)

# 准备发送的数据
message = "Hello, Server!".encode()

# 使用select进行IO多路复用
inputs = [client_socket]
outputs = [client_socket]

while outputs:
    # 使用select进行IO多路复用
