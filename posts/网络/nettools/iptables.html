iptables

iptables 是linux系统提供的配置防火墙的工具 linux防火墙是由内核Netfilter模块实现的 iptables只适用于ipv4包的处理，如果是ipv6包，则使用ip6tables命令

iptables、ip6tables等都使用Xtables框架。存在“表（tables）”、“链（chain）”和“规则（rules）”三个层面。

每个“表”指的是不同类型的数据包处理流程，如filter表表示进行数据包过滤，而nat表针对连接进行地址转换操作。每个表中又可以存在多个“链”，系统按照预订的规则将数据包通过某个内建链，例如将从本机发出的数据通过OUTPUT链，则会依次执行含有output链的各个表中output链的规则。在“链”中可以存在若干“规则”，这些规则会被逐一进行匹配，如果匹配，可以执行相应的动作(target)，如ACCEPT, DROP, REJECT, to jump to another chain，or some other custom action。 when a packet doesn't match any rules in a chain,将根据该链的默认策略（“policy”）执行对应动作；如果也没有默认policy，则是返回调用者链。

iptables一共有4个表

  • filter表 filter通常用于过滤数据包。其中的内建链包括： INPUT，输入链。发往本机的数据包通过此链。 OUTPUT，输出链。从本机发出的数据包通过此链。 FORWARD，转发链。本机转发的数据包通过此链。
  • nat表 nat表如其名，用于地址转换操作。其中的内建链包括： PREROUTING，路由前链，在处理路由规则前通过此链，通常用于目的地址转换（DNAT）。 POSTROUTING，路由后链，完成路由规则后通过此链，通常用于源地址转换（SNAT）。 OUTPUT，输出链
  • mangle表 mangle表用于处理数据包。其和nat表的主要区别在于，nat表侧重连接而mangle表侧重每一个数据包。其中内建链列表如下。 PREROUTING OUTPUT FORWARD INPUT POSTROUTING
  • raw表 raw表用于配置连接跟踪的豁免。有如下两个内建链： PREROUTING OUTPUT ``` 连接跟踪(Connection tracking) Connection tracking is a feature of many firewalls and similar devices that allows the device to maintain state information about a network session, such as TCP streams or UDP communication, which includes source and destination IP addresses, port number pairs, protocol types, and more.

raw表的规则一般是如果某个package符合rules,则target是NOTRACK，也就是不跟踪链接 The NOTRACK target is a special target that, when a packet matches a rule with this target, disables connection tracking for this packet.

So, the raw table in iptables is used to specify certain network traffic that should not be tracked by the connection tracking system. This is done in the earliest stages of packet handling (PREROUTING for incoming packets, OUTPUT for outgoing ones) to prevent any further processing overhead associated with tracking these connections.


几个常用表的优先级
mangle -->nat --> filter.
比如我们有一个outgoing packet, it will go through the output chain first, the order of the tables  for an outgoing packet (OUTPUT chain) is as follows:mangle -->nat --> filter.

the raw table can also be involved if connection tracking is to be bypassed. In that case, it would be the first table to be processed.

The security table is usually used by SELinux and it's not commonly manually configured. If it's used, it would be processed after the filter table.
iptables 表的作用，就是在某个具体的“检查点”（比如 Output）上，按顺序执行几个不同的检查动作（比如，先执行 nat，再执行 filter）。



内核预定义了5个规则链，每个规则链对应一个Netfilter hooks。预定义的链有一个对包的基础处理策略（policy）,比如ACCEPT,当包顺着链中的规则依次处理后到达链尾（通常所有的rule都不匹配时），会应用这个策略。
用户可以自定义链,自定义的链没有基础处理策略，当到达末尾后会返回调用的链
一个链可以是空的。
预定义的5个链: prerouting,input,forward,output,postrouting
链中的每个规则主要是包的匹配说明，以及一个action,也就是target，跳转到别的链或者accept,drop，return等

PREROUTING：数据包刚到达时会经过这个点，通常用来完成DNAT的功能。
INPUT：数据包要进入本机的传输层时会经过这个点，通常用来完成防火墙入站检测的功能。
FORWARD：数据包要通过本机转发时会经过这个点，通常用来过滤数据包。
OUTPUT：从本机的数据包要出去的时候会经过这个点，通常用来做DNAT和包过滤。
POSTROUTING：数据包离开本机前会经过这个点，通常用来做SNAT。



本机发出的包：本机进程 -> OUTPUT 链 -> 路由选择 -> POSTROUTING 链 -> 出口网卡
本机收到的包：入口网卡 -> PREROUTING 链 -> 路由选择 -> 此时有两种可能的情况
目的地址为本机：INPUT 链 -> 本机进程
目的地址不为本机：FORWARD 链 -> POSTROUTING 链 -> 网卡出口（内核允许网卡转发的情况下）


常用的action
* ACCEPT： 允许数据包通过
* DROP： 直接丢弃数据包，不给任何回应信息，这时候客户端会感觉自己的请求泥牛入海了，过了超时时间才会有反应
* QUEUE： Pass the packet to userspace.When a packet matches a rule with the QUEUE target, it is enqueued to the nfqueue(Netfilter Queue) packet queue. A userspace process can then dequeue the packet for processing (such as using library `nfqueue` in python). After processing, the userspace process can decide whether to ACCEPT or DROP the packet, or to ask iptables to continue processing the packet with the next rule.This is often used for more complex processing that can't be done within the kernel or to integrate with custom software or third-party solutions.
* RETURN： 停止执行当前链中的后续规则，并返回到调用链中
* REJECT： 拒绝数据包通过，必要时会给数据发送端一个响应的信息
* DNAT： 目标地址转换
* SNAT： 源地址转换
* MASQUERADE： 是 SNAT 的一种特殊形式，适用于动态的、临时会变的 ip 上
  The "MASQUERADE" target in iptables is used in NAT (Network Address Translation) settings. It allows a system to act as a gateway for a network, where all traffic originating from the network is masqueraded as originating from the gateway system itself. This is typically used when the system's IP address is dynamically assigned, as it does not require the IP address to be known at the time the rules are set.
  比如如下设置

iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

  This command appends a rule to the POSTROUTING chain of the nat table (-t nat -A POSTROUTING), specifying that any packets going out over eth0 should be masqueraded (-o eth0 -j MASQUERADE).
  这里并不需要设置具体的转换后的ip地址。

* REDIRECT
  The REDIRECT target in iptables is used to redirect packets and streams to the machine itself. It alters the destination IP address to send the packet to the local machine. It's commonly used for transparent proxying, where you redirect packets that are   for a certain port to a local socket, where a service is listening.

iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080


  This command will redirect all incoming packets destined for port 80 to port 8080 

* LOG： 记录日志信息，除记录外不对数据包做任何其他操作，仍然匹配下一条规则


使用

iptables [-t table] commands rules

如果-t省略，默认为filter表

commands
* -A --append  在指定链的末尾添加一条新的规则
* -I --insert    在指定链中插入一条新的规则，默认在链的开头插入
* -R --replace    修改、替换指定链中的一条规则，按规则序号或内容确定
* -F, --flush    清空指定链上面的所有规则，如果没有指定链，清空表上所有链的所有规则
* -N --new    新建一条用户自己定义的规则链
* -X --delete-chain    删除指定表中用户自定义的规则链
* -P --policy    设置指定链的默认策略
* -L --list    列出指定链中的所有的规则进行查看，如果没有指定链，默认列出表中所有链的内容
* -S --list-rules    以原始格式列出链中所有规则
* --line-number    查看规则列表时，同时显示规则在链中的顺序号
* -v --verbose    查看规则列表时显示详细的信息
* -n --numeric    用数字形式显示输出结果，如显示主机的 IP 地址而不是主机名

rules 
* -i --in-interface    匹配输入接口，如 eth0，eth1
* -o --out-interface    匹配输出接口
* -p --proto    匹配协议类型，如 TCP、UDP 和 ICMP等
* -s --source    匹配的源地址
* -d --destination    匹配的目的地址
* -m --match 使iptables加载指定模块(extension modules)来做更进一步的规则匹配。
  可以加载的模块如下
  * limit: This module matches at a limited rate using a token bucket filter. A rule using this extension will match until this limit is reached.

iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m limit --limit 3/min --limit-burst 3 -j ACCEPT iptables -A INPUT -p tcp --dport 22 -m state --state NEW -j DROP

  the first rule allows up to 3 new SSH (--dport 22) connections per minute. If this limit is reached, the rule will stop matching and the next rule will be evaluated.

  The `--limit-burst 3` option specifies the maximum number of matches that can occur in a burst, effectively allowing a short burst of packets at the beginning.

  The second rule drops all new SSH connections that are not matched by the first rule. This effectively limits the rate of new SSH connections to 3 per minute, dropping all others.

  我们也可以省略`--limit-burst 3 ` option,如果被省略，他的默认值是5，也就是说，如果我们如下设置

iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m limit --limit 3/min -j ACCEPT iptables -A INPUT -p tcp --dport 22 -m state --state NEW -j DROP

  In this case, the first rule will allow up to 3 new SSH connections per minute. If this limit is reached, the rule will stop matching and the second rule will be evaluated, which drops the new SSH connections. However, because the --limit-burst defaults to 5, you will initially be able to make 5 new connections quickly before the limit of 3 connections per minute is enforced.




  * mac: This module matches on a specific MAC address.

iptables -A INPUT -m mac --mac-source 00:0c:29:4f:23:ac -j DROP


  * mark: match packets based on marks associated with them.The mark module can be used in conjunction with the MARK target to set marks on packets for further processing.

iptables -t mangle -A PREROUTING -p tcp --dport 80 -j MARK --set-mark 1 iptables -t nat -A PREROUTING -m mark --mark 1 -j REDIRECT --to-port 8080

  In this example, the first command marks all incoming TCP packets destined for port 80 with a mark of 1. The second command matches packets with a mark of 1 and redirects them to port 8080.

  * multiport: This module matches a set of source or destination ports.

  * state: This module matches the connection state.The state module of iptables is used to track the state of a connection. It can be useful in many situations, such as allowing related and established connections while blocking new ones from the outside.
  ```shell
  # Allow established and related incoming connections
  iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

  # Allow new outgoing connections
  iptables -A OUTPUT -m state --state NEW,ESTABLISHED,RELATED -j ACCEPT

  # Block new incoming connections
  iptables -A INPUT -m state --state NEW -j DROP

连接状态有4种： NEW: The packet is starting a new connection, or is associated with a connection which has not seen packets in both directions.

ESTABLISHED: The packet is associated with a connection which has seen packets in both directions.

RELATED: The packet is starting a new connection, but is associated with an existing connection, such as an FTP data transfer, or an ICMP error.

INVALID: The packet does not match any known connection, is out of sequence, or fails TCP timestamp validation. In general, such packets should be dropped.

  • tcp: This module matches if the TCP protocol is used.
    iptables -A INPUT -p tcp -m tcp --dport 22 -j ACCEPT
    In this example, the -m tcp option tells iptables to load the tcp module. This allows the use of TCP protocol specific options, such as --dport to specify the destination port.

  • udp: This module matches if the UDP protocol is used.

  • icmp: This module matches if the ICMP protocol is used.

  • length: This module matches the length of a packet.

  • owner: The owner module in iptables is used to match packets based on the identity of the process that created them.This module is only valid in the OUTPUT and POSTROUTING chains, and allows you to match packets based on the user ID, group ID, process ID, session ID and command name of the process that created them.

    iptables -A OUTPUT -m owner --uid-owner 1001 -j DROP

    In this example, the rule will drop all packets that are created by the user with the ID 1001.

常用实例:

查看规则：

iptables -nvL
iptables -t nat -nvL

显示规则序号

iptables -nvL INPUT --line-numbers
iptables -t nat -nvL --line-numbers
iptables -t nat -nvL PREROUTING --line-numbers

查看规则的原始格式

iptables -t filter -S
iptables -t nat -S
iptables -t mangle -S
iptables -t raw -S

清除所有规则：

iptables -F  # 清空表中所有的规则
iptables -X  # 删除表中用户自定义的链
iptables -Z  # 清空计数

iptables -t nat -F
iptables -t nat -X
iptables -t mangle -F
iptables -t mangle -X
iptables -t raw -F
iptables -t raw -X
iptables -t security -F
iptables -t security -X

设置默认policy：

iptables -P INPUT DROP     # 配置默认丢弃访问的数据表
iptables -P FORWARD DROP   # 配置默认禁止转发
iptables -P OUTPUT ACCEPT  # 配置默认允许向外的请求

增加、删除、修改规则： 增加一条规则到最后

iptables -A INPUT -i eth0 -p tcp --dport 80 -m state --state NEW,ESTABLISHED -j ACCEPT

注：以下几条操作都需要使用规则的序号，需要使用 -L --line-numbers 参数先查看规则的序号

插入一条规则到指定位置

iptables -I INPUT 2 -i eth0 -p tcp --dport 80 -m state --state NEW,ESTABLISHED -j ACCEPT

删除一条规则

iptabels -D INPUT 2

修改一条规则

iptables -R INPUT 3 -i eth0 -p tcp --dport 80 -m state --state NEW,ESTABLISHED -j ACCEPT

允许本地回环接口

iptables -A INPUT -i lo -j ACCEPT

允许已建立的或相关连接的通行

iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

允许所有本机向外的访问

iptables -A OUTPUT -j ACCEPT

允许 22,80,443 端口的访问

iptables -A INPUT -p tcp --dport 22 -j ACCEPT
iptables -A INPUT -p tcp --dports 80,443 -j ACCEPT

如果有其他端口的需要开放，则同上

iptables -A INPUT -p tcp --dport 8000:8010 -j ACCEPT

允许 ping

iptables -A INPUT -p icmp -m icmp --icmp-type 8 -j ACCEPT

禁止其他未允许的规则访问

iptables -A INPUT -j REJECT
iptables -A FORWARD -j REJECT

注：以上操作需要一定的顺序，确保规则顺序正确

目的地址转换，首先需要在内核中开启转发功能（源地址转换也需要开启）

echo 1 > /proc/sys/net/ipv4/ip_forward

把从 eth0 进来要访问 TCP/80 的数据包的目的地址转换到 192.168.1.18

iptables -t nat -A PREROUTING -p tcp -i eth0 --dport 80 -j DNAT --to 192.168.1.18

把目的地址123.57.172.149 ，端口80 的tcp数据包的目的地址转换到 192.168.1.118:8000

iptables -t nat -A PREROUTING -p tcp -d 123.57.172.149 --dport 80 -j DNAT --to 192.168.1.118:8000

最典型的应用是让内网机器可以访问外网： 将内网 192.168.0.0/24 的源地址修改为 1.1.1.1 (可以访问互联网的机器的 IP)

iptables -t nat -A POSTROUTING -s 192.168.0.0/24 -j SNAT --to 1.1.1.1

将内网机器的源地址修改为一个 IP 地址池

iptables -t nat -A POSTROUTING -s 192.168.0.0/24 -j SNAT --to 1.1.1.1-1.1.1.10

持久化规则： 保存当前规则

iptables-save > iptables.20190721

恢复备份规则

iptables-restore < iptables.20190721
