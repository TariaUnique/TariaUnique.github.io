11 DNS协议

DNS（Domain Name System，域名系统）协议将人类可读的域名（如 www.example.com）转换为机器可读的IP地址（如 192.0.2.1）。DNS协议的工作原理可以通过以下几个步骤来描述：

1) 域名解析请求： 当用户在浏览器中输入一个域名或点击一个链接时，他们的计算机会首先检查本地DNS缓存，看看是否之前已经解析过该域名。如果缓存中没有找到，计算机会向配置的DNS服务器发送一个解析请求。Linux系统上，这样的服务器通常配置在/etc/resolv.conf文件中,这样的DNS服务器被称为DNS递归查询服务器或者叫做递归解析器。 2) 递归查询： 客户端向DNS递归查询服务器发送一个递归查询。 如果该服务器中没有缓存的解析结果，则向互联网上配置的根服务器发送请求。递归查询是指客户端向DNS递归查询服务器发送一个查询请求，并期望DNS递归查询服务器提供一个完整的答案，即最终的IP地址。如果该服务器没有缓存所需的解析信息，它将作为递归解析器，代表客户端向其他DNS服务器发起查询，直到获取到所需的IP地址。在递归查询中，DNS服务器负责处理整个查询过程，客户端只需要发送一次请求，然后等待接收最终结果。 3) 迭代查询： 递归解析器向其他DNS服务器发送查询请求，DNS服务器收到查询请求后，如果它没有所需的信息，它会返回一个指向另一个可能拥有所需信息的DNS服务器的地址。递归解析器收到这个地址后，需要自己向这个新的DNS服务器发送查询请求。这个过程会一直重复，直到找到权威DNS服务器并获取到最终的IP地址 4) 权威DNS服务器： 权威DNS服务器是负责特定域名解析的服务器。它们存储着域名与IP地址之间的映射信息。当递归解析器找到权威DNS服务器后，它会向权威DNS服务器发送查询请求。 5) 响应： 权威DNS服务器收到查询请求后，会返回一个包含IP地址的响应给递归解析器。递归解析器再将这个响应返回给用户的计算机。 6) 缓存结果： 为了提高解析效率，减少延迟，递归DNS服务器会在本地缓存查询结果一段时间。下次有相同的域名查询时，递归DNS服务器可以直接使用缓存信息，而不需要再次查询。 7) TTL（生存时间）： DNS响应中包含一个TTL值，指定了该记录可以在缓存中保留的时间。TTL过期后，递归DNS服务器将需要重新查询以获取最新的信息。 8) DNS协议使用UDP作为传输层协议，通常使用端口53。

DNS服务器
  • 当递归DNS服务器没有该域名的本地缓存时，需要向互联网上的其他域名服务器发送迭代查询。互联网上的其他域名服务器根据域名组成树状的结构，比如example.com.域名，最后的.代表根域名服务器，根域名服务器是DNS层次结构的顶部，它们管理着DNS根域（通常表示为单个点.）,该服务器中包含了关于顶级域（如.com、.org、.net等）的DNS服务器的信息。当进行DNS查询时，如果递归查询服务器不知道如何解析一个域名，它会向根域名服务器查询以获取指向相应顶级域服务器的信息。全球共有13组根域名服务器，每组有多台服务器构成，以确保高可用性和可靠性。
  • 而.com则为顶级域服务器，顶级域服务器进一步负责管理各自域下的二级域名example.com，并维护指向这些域名的权威DNS服务器的信息。
  • 权威DNS服务器是负责特定域名解析的服务器。它们存储着域名与IP地址之间的映射信息，以及其他相关的DNS记录。当一个域名被解析时，最终的查询会发送到该域名的权威DNS服务器，这些服务器会返回正确的IP地址或其他DNS记录。例如，example.com的权威DNS服务器将负责处理所有与example.com相关的DNS查询。

不同的DNS服务器通常被设置在不同的位置，以满足全球范围内的域名解析需求。

  • 根域名服务器被分布在全世界各地，以确保全球范围内的可靠性和性能。它们通常位于数据中心，这些数据中心由各种组织运营，包括学术机构、私营公司和国际组织。根域名服务器的分布设计考虑到了地理位置的多样性，以减少由于地理位置远导致的延迟，并提高DNS查询的整体效率。
  • 顶级域服务器通常由各个顶级域的管理机构运营。例如，.com顶级域由Verisign公司运营，而.org顶级域由Public Interest Registry运营。这些服务器也可能位于全球不同的数据中心，以提供高效的服务。顶级域服务器通常会选择地理位置优越、网络基础设施发达的地方作为部署地点。
  • 权威DNS服务器： 权威DNS服务器通常由域名所有者或其委托的DNS服务提供商运营。这些服务器可以位于任何地方，包括企业的内部网络、云服务提供商的数据中心，或者专业的DNS托管服务提供商的设施中。
  • linux系统中，/etc/resolv.conf中配置有递归DNS服务器（recursive DNS server）的地址。当你的系统尝试解析一个域名时，它会向这些递归DNS服务器发送查询请求。递归DNS服务器的工作是负责完成整个DNS解析过程，包括向根域名服务器、顶级域服务器和权威DNS服务器发送查询，直到找到域名的IP地址。这个文件通常由网络配置脚本或服务在系统启动或网络接口激活时自动生成。在大多数情况下，/etc/resolv.conf 中配置的DNS服务器是以下几种类型之一：
    • 本地网络中的DNS服务器： 如果你的Linux系统连接到了一个本地网络（如家庭、办公室或学校网络），/etc/resolv.conf 中可能会列出该网络的DNS服务器地址。这些服务器通常由网络管理员或互联网服务提供商（ISP）管理，以便为本地网络中的设备提供DNS解析服务。
    • ISP的DNS服务器： 互联网服务提供商通常会为他们的客户提供一组DNS服务器，这些服务器会在/etc/resolv.conf 中自动配置，以便用户能够访问互联网上的资源。
    • 公共DNS服务器： 有时，/etc/resolv.conf 中可能会配置一些公共DNS服务器的地址，如Google的8.8.8.8和8.8.4.4，Cloudflare的1.1.1.1，或者OpenDNS的服务器等。这些公共DNS服务器由第三方组织提供，任何人都可以使用它们来进行域名解析。
    • 自定义DNS服务器： 如果用户有特殊需求，他们可能会手动编辑/etc/resolv.conf 文件，添加自定义的DNS服务器地址。这可能是为了提高解析速度、过滤不合适的内容或者实现特定的网络策略。 例如，一个典型的/etc/resolv.conf文件可能包含如下内容：
      nameserver 192.168.1.1
nameserver 8.8.8.8
      这里，192.168.1.1 可能是本地网络中的DNS服务器，而 8.8.8.8 是Google的公共DNS服务器。
DNS记录

DNS记录（也称为DNS资源记录）是存储在DNS服务器上的信息记录，它们定义了域名与IP地址之间的映射关系，以及其他跟该域名有关的信息。以下是一些常见的DNS记录类型：

  • A记录（Address Record）：example.com. A 192.0.2.1 域名与IPv4地址的映射
  • AAAA记录（IPv6 Address Record）：example.com. AAAA 2001:db8::1 域名与IPv6地址的映射
  • CNAME记录（Canonical Name Record）： 域名的别名 www.example.com. CNAME example.com.
  • MX记录（Mail Exchanger Record）：example.com. MX 10 mail.example.com. 该域名下的邮件服务器，优先级为10（数值越低优先级越高）。
  • TXT记录（Text Record）：example.com. TXT "v=spf1 mx -all" 域名的附加信息，常用于域名验证、SPF（发件人策略框架）记录等。
  • NS记录（Name Server Record）：example.com. NS ns1.example.com. 指定负责解析该域名的权威DNS服务器。
  • CAA记录（Certification Authority Authorization Record）：example.com. CAA 0 issue "letsencrypt.org" 用于指定哪些证书颁发机构（CA）被允许为该域名颁发证书。 这表示只有letsencrypt.org证书颁发机构被授权为example.com颁发证书。

关于authority records section 和 additional records section 的更详细的解释:

  • Authority Records Section: This section contains records that help in reaching the authoritative DNS server for the queried domain. These are typically Name Server (NS) records. For example, if you query for www.example.com and the DNS server you first ask doesn't know the answer, it might provide NS records for example.com in the authority section, pointing you to DNS servers that have more specific knowledge.

  • Additional Records Section: This section contains additional useful records not directly related to the query but related to the records in the answer and authority sections. A common use of the additional section is to provide "glue records". A glue record is an A or AAAA record for a nameserver, provided in addition to the NS record, to avoid a separate lookup to resolve the nameserver's name.
