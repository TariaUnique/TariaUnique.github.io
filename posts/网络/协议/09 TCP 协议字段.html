09 TCP 协议字段

Data offset: TCP的头部可能会有Options部分，因此是变长的。Data offset代表了头部的长度。单位是32bit word,也就是4字节。也就是tcp header最长可以使60字节。没有options的话是20字节

Checksum: 会校验包括 TCP header, the data payload, and a pseudo header. The pseudo header is not transmitted as part of TCP segment, but is included in the checksum calculation. It consists of the source IP address, the destination IP address, the protocol number for TCP, and the length of the TCP data.

NS(Nonce Sum) , CWR(Congestion Window Reduced), ECE(ECN-Echo), 这些都是跟tcp的拥塞控制相关，略

PSH(push):The PSH flag in the TCP header is used to tell the receiving host that the data should be pushed up to the receiving application immediately, instead of being buffered. This is typically used when the sending application has reached a point where it wants to ensure all previously sent data is delivered to the receiving application before delivering more data. 需要注意的是，app 获取data是需要主动去读的，如果app正在忙于做别的事，那么data还是要被buffer在缓存中。所以这里的意思，准确的说是，接收端收到PUSH data时，应该立即通知上层数据到了，可以获取了。

RST：重置。当收到这个segment时，接收端需要立刻重置连接，所有缓存的数据都被丢失。有以下情况会发送RST segment

  • An unexpected packet: If a TCP packet arrives that doesn't belong to any existing connection, a TCP RST packet is sent back in response.
  • Refusal of a connection request: If a request to open a connection is refused, a RST packet is sent back.
  • Abnormal close: If an application closes its TCP connection without the standard TCP connection termination process (FIN, ACK), a RST packet is sent to let the other end know that the connection has been closed.
  • In response to some kinds of errors. For example, if a service on the destination server is not available, it may respond with a RST packet.

URG and urgent pointer: URG表示当前的数据中有紧急数据，urgent pointer 表示紧急数据到哪里结束。比如如果seq是5000，而urgent pointer 是200， 则5000-5200是紧急数据。

Options: 这部分最长是40个字节，存储不同的options. 每个option的长度不定，但都需要4字节对齐。如果没有4字节对齐的，中间需要padding. 每个options的格式有所不同，但大多包含如下三部分：

  • Option-Kind (1 byte): This field indicates the type of option, and it's a single byte in size. Each option has a unique Option-Kind.
  • Option-Length (1 byte, optional): This field indicates the total length of the option, including the Option-Kind and Option-Length fields. This field is only present if the Option-Kind requires it.
  • Option-Data (variable length, optional): This field contains the actual data or parameters for the option. The length of this field is determined by the Option-Length field.

Option-Kind 有如下

  • Maximum Segment Size (MSS): Option-Kind: 2 Option-Length: 4 Option-Data: 2 bytes representing the MSS. This option is used to specify the maximum amount of data that a device can accept in a single TCP segment. 这个数据会在SYN /SYN-ACK segment中被确定。通常不会大于MTU。

  • Window Scale: Option-Kind: 3 Option-Length: 3 Option-Data: 1 byte representing the shift count. This option is used to increase the maximum window size from 65,535 bytes to 1 gigabyte. 如果这个option被传输，比如值为X, 则之后的window size需要乘以2^X 如果要设置的话，通常也是在SYN / SYN-ACK中被设置

  • Timestamps Option-Kind: 8 Option-Length: 10 Option-Data: 4 bytes for the timestamp value(TSval), 4 bytes for the timestamp echo reply(TSecr). TSval是当前的时间，TSecr是之前收到的消息的TSval.比如A给B发segment, 其中TSval是1000.B收到消息，给A回复(whether it's an acknowledgement, data, or both),其TSval是B发消息的时间，而TSecr为1000，这样A收到消息，假设当前时间是2500，则2500-1000为1500，为rtt时间。rtt的采样时间用于计算rto时间

  • Selective Acknowledgements (SACK): Option-Kind: 5 Option-Length: Variable Option-Data: Variable, contains the left and right edges of each block of data being acknowledged.

    This option is used to acknowledge non-contiguous blocks of data, which can improve performance in the presence of packet loss.

  • SACK-Permitted: Option-Kind: 4 Option-Length: 2 No Option-Data field. This option is set in the SYN and SYN-ACK segments to indicate that the sender supports the Selective Acknowledgement (SACK) option.

  • No-Operation (NOP): Option-Kind: 1 No Option-Length or Option-Data fields. This option is used for padding
  • End of Option List (EOL): Option-Kind: 0 No Option-Length or Option-Data fields. This option specifies the end of the option list.
PS1

how the SACK and SACK-Permitted be used?

Selective Acknowledgment (SACK) and SACK-Permitted are TCP options used to improve performance in the case of packet loss. Here's how they work:

SACK-Permitted: This is a two-byte option that a host can use to indicate that it supports the SACK option. It's typically included in the SYN and SYN-ACK packets during the TCP three-way handshake. If both hosts include the SACK-Permitted option, they can then use the SACK option in later packets.

SACK: This option is used to acknowledge non-contiguous blocks of data. Normally, TCP uses cumulative acknowledgments, meaning that it acknowledges all contiguous data up to a certain point. If packets are lost, this can lead to unnecessary retransmissions.

For example, suppose a host receives packets 1, 2, 4, and 5, but packet 3 is lost. With cumulative acknowledgments, the host can only acknowledge up to packet 2, so packets 4 and 5 would need to be retransmitted even though they were received.

With SACK, the host can acknowledge packets 1, 2, 4, and 5, and only packet 3 needs to be retransmitted. The SACK option includes the left and right edges of each block of data being acknowledged. So in this case, the SACK option might look like this: [1, 2], [4, 5].

This can significantly improve performance on links with high latency or packet loss.
