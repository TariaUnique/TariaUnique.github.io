01 单例模式

单例设计模式（Singleton Design Pattern）

一个类只允许创建一个对象，那这个类就是一个单例类，这种设计模式就叫作单例设计模式

  • 饿汉式 使用global static object实现。因为global static object在程序启动时就构造好了，所以叫饿汉式 ```c++

    include

    class A{ public: static A& getInstance(){
      return a;
    } void func(){} private: A(){} A(const A& a)=delete; A(A&& a)=delete; static A a; };

A A::a;

int main(){ A::getInstance().func(); }



* 懒汉式
使用local static variable实现。因为local static variable在程序运行时第一次调用到getInstance()的时候再进行构造，所以叫懒汉式。

```c++
#include <iostream>

class A{
public:
   static A& getInstance(){
        static A a;
        return a;
    }
    void func(){}
private:
    A(){}
    A(const A& a)=delete;
    A(A&& a)=delete;
};


int main(){
         A::getInstance().func();
}

以上的实现都没有线程安全问题。global static object的初始化是在程序启动时初始化的。而static local variable虽然是在运行时第一次调用到getInstance()时才初始化，但如果是多线程调用，in C++11 and later, the initialization of local static variables is guaranteed to be thread-safe. This means that if multiple threads call the getInstance method simultaneously, only one thread will create the instance, and the others will wait until the instance is fully constructed.

同时，global objects的初始化顺序是我们无法保证的，如果不同global objects之间有依赖关系，那么可能会出现被依赖的对象还没有创建的可能性。

线程唯一的单例模式

也就是一个线程只能创建一个对象，而不是整个进程创建一个对象，可以直接使用thread_local关键字

  • 使用global thread_local static object,也就是饿汉式加了thread_local关键字 ```c++

    include

    include

    class A{ public: static A& getInstance(){
      return a;
    } void func(){
      std::cout<<"thread id "<<std::this_thread::get_id()<< std::endl;
    } private: A(){
      std::cout<<"constructed now"<<std::endl;
    } ~A(){
       std::cout<<"destructed now"<<std::endl;
    } A(const A& a)=delete; A(A&& a)=delete; static thread_local A a; };

thread_local A A::a;

void threadfunc(){ A::getInstance().func(); }

int main(){ std::cout<<"start main"<<std::endl; A::getInstance().func(); std::thread t1(threadfunc); std::thread t2(threadfunc); t1.join(); t2.join(); std::cout<<"thread joined"<<std::endl; std::cout<<"end main"<<std::endl;

}

结果
```shell
start main
constructed now
thread id 140310348125120
constructed now
constructed now
thread id 140310348109376
destructed now
thread id 140310339716672
destructed now
thread joined
end main
destructed now

可以看到，现在对象的创建不再是程序启动时了，而是线程访问到的时候再创建 同时，析构是在线程析构的时候进行。

  • 使用 static local varible predeclared with thread_local ```c++

    include

    include

    class A{ public: static A& getInstance(){
      static thread_local A a;
  return a;
    } void func(){
      std::cout<<"thread id "<<std::this_thread::get_id()<< std::endl;
    } private: A(){
      std::cout<<"constructed now"<<std::endl;
    } ~A(){
       std::cout<<"destructed now"<<std::endl;
    } A(const A& a)=delete; A(A&& a)=delete;

};

void threadfunc(){ A::getInstance().func();

}

int main(){ std::cout<<"start main"<<std::endl; A::getInstance().func(); std::thread t1(threadfunc); std::thread t2(threadfunc); t1.join(); t2.join(); std::cout<<"thread join"<<std::endl; std::cout<<"end main"<<std::endl;

}

结果一样的，也是在线程访问的时候再创建，在线程析构的时候析构对象




##### 多例模式
很灵活，根据需求来
```c++
#include <iostream>

class A{
public:
    static A& getInstance(int i){
        return a[i];
    }
    void func(){}
private:
    static A a[3];
    A(){
        std::cout<<"constructed now"<<std::endl;
    }
    ~A(){
         std::cout<<"destructed now"<<std::endl;
    }
    A(const A& a)=delete;
    A(A&& a)=delete;
};
A A::a[3]= {A{},A{},A{}};

int main(){
    std::cout<<"start main"<<std::endl;
    A::getInstance(0).func();
    std::cout<<"end main"<<std::endl;
}
PS

我在测试时，偶尔出现了输出互相交错的情况,如下

start main
constructed now
thread id constructed now
thread id 140079415510592
destructed now
140079423903296
destructed now
thread joined
end main

很明显，多线程同时访问std::cout,我在程序中使用的输出方式，一条以\n结束的语句，中间多次调用的输出操作operator<<,首先，多次调用输出操作是低效的。其次，在多线程并发访问std::cout输出缓冲区的情况下，会出现结果交错的情况。 这条语句的第一个输出，"thread id "

 std::cout<<"thread id "<<std::this_thread::get_id()<< std::endl;

和这条语句的第一个输出"constructed now"

std::cout<<"constructed now"<<std::endl;

互相交错了。

如何避免呢？ 我们可以使用std::ostringstream,先将整条语句都输出到stringstream中，再只调用一次std::cout的输出操作。如下：

std::ostringstream oss;
oss<<"thread id "<<std::this_thread::get_id()<< std::endl;
std::cout << oss.str();

这样可以有效避免一条输出语句的多个部分和并发输出的另一条语句的多个部分之间的交错。

改正之后的代码

#include <iostream>
#include <thread>
#include <sstream>

class A{
public:
    static A& getInstance(){
        return a;
    }
    void func(){
        std::ostringstream oss;
        oss<<"thread id "<<std::this_thread::get_id()<< std::endl;
        std::cout << oss.str();
    }
private:
    A(){
        std::cout <<"constructed now\n";
    }
    ~A(){
        std::cout <<"destructed now\n";
    }
    A(const A& a)=delete;
    A(A&& a)=delete;
    static thread_local  A a;
};

thread_local A A::a;

void threadfunc(){
    A::getInstance().func();
}

int main(){
        std::cout<<"start main\n";
       // A::getInstance().func();
        std::thread t1(threadfunc);
        std::thread t2(threadfunc);
        t1.join();
        t2.join();
        std::cout<<"thread joined\n";
        std::cout<<"end main\n";

}

多线程输出就没有交错了
