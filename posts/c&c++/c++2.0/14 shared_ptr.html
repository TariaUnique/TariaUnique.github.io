14 shared_ptr

智能指针

使用传统的指针手动管理内存，会存在以下等问题：

  • Memory leaks: If you forget to call delete, dynamically allocated memory is not freed.
  • Dangling pointers: If you call delete but continue using the pointer, you can access freed memory, leading to undefined behavior.
  • Double deletions: Deleting the same memory twice can lead to undefined behavior, often causing crashes or corruption of memory.
  • Exception unsafe: 在抛出异常的情况下，使用指针管理的内存会有内存泄露的可能。异常栈在展开时不会释放指针管理的内存。

c++11提供的智能指针，旨在提供以下的功能：

  • Automatic Resource Management ensure that resources are properly cleaned up when they are no longer needed
  • Exception Safety 在抛出异常的情况下，使用智能指针管理的内存也会被合适的处理，需要释放的时候会被释放。

主要功能

Allows shared ownership of a resource. Multiple shared_ptrs can manage the same resource, and the resource is automatically freed when the last shared_ptr goes out of scope

内部实现

一个shared_ptr的实现，包括两个指针

  • the stored pointer (one returned by get())
  • a pointer to control block

control block中含有如下

  • either a pointer to the managed object or the managed object itself
  • the deleter (type-erased)
  • the allocator (type-erased)
  • the number of shared_ptrs that own the managed object
  • the number of weak_ptrs that refer to the managed object
stored_pointer

stored_pointer是用于alias constructor的，详见后文。

control block
  • either a pointer to the managed object or the managed object itself 如果我们构造shread_ptr是传递的已经构造好的对象的指针，这个指针就被存储到这里。当我们使用make_shared创建shared_ptr时，如果对象很小，make_shared可能就会使用in-place allocation,将对象直接创建在control block中。这叫sso(small object optimilization), 既减少了内存分配的次数，也可以避免小对象造成的内存碎片。 比如std::shared_ptr<int> ptr(new int(42)); 我们直接new好了对象，再将对象传递给shared_ptr管理，虽然int很小，但不会被sso优化。而如果是std::shread_ptr<int> ptr = std::make_shared<int>(42);，这时候，对象的分配就可能会使用sso优化，直接分配在control block中。
  • the deleter (type-erased) 这个是在最后一个shared_ptr goes out of scope 后释放对象时需要调用的析构函数。之所以是type_erased，是为了在shared_ptr可以在clean up object时，不需要知道对象的类型。这在有继承的情况下非常有用。比如shared_ptr<Base>管理的是派生对象Derived,而Base中的析构函数不是virtual的，这时候在对象析构时，一样能正确的调用到派生对象的析构函数。而unique_ptr就做不到了。unique_ptr这时候就会只调用Base的析构函数。 type-erased deleter通常使用void (*)(void*) 函数指针，其中的参数是void*的，任何类型的对象指针都可以转换成void*。当然，我们也可以在构造时传递自己的deleter,只要是任何符合签名的可调用对象即可。（任何类型都可以转换成void*，所以对类型没有要求）

  • the allocator (type-erased) The allocator is an optional component in std::shared_ptr that allows you to specify the memory allocation strategy for the managed object. By default, std::shared_ptr uses the global ::opereator new ()for memory allocation, but you can provide a custom allocator to control how memory is allocated and deallocated for the managed object. Similar to the deleter, the allocator is type-erased. The type-erasure mechanism allows std::shared_ptr to store a generic allocator that can allocate memory for any type of object. The allocator is usually a callable object that has an allocate() and deallocate() methods. Example

    #include <iostream>
#include <memory>

template <typename T>
struct MyAllocator {
    using value_type = T;

    MyAllocator() = default;

    template <typename U> 
    MyAllocator(const MyAllocator<U>&) {}

    T* allocate(std::size_t n) {
        std::cout << "Custom allocating " << n << " elements" << std::endl;
        return static_cast<T*>(::operator new(n * sizeof(T)));
    }

    void deallocate(T* ptr, std::size_t n) {
        std::cout << "Custom deallocating " << n << " elements" << std::endl;
        ::operator delete(ptr);
    }
};

int main() {
    std::shared_ptr<int> ptr = std::allocate_shared<int>(MyAllocator<int>(), 42);
    return 0;
}

    Output

    Custom allocating 1 elements
Custom deallocating 1 elements
  • the number of shared_ptrs that own the managed object The destructor of shared_ptr decrements the number of shared owners of the control block. If that counter reaches zero, the control block calls the destructor of the managed object. The control block does not deallocate itself until the std::weak_ptr counter reaches zero as well.
  • the number of weak_ptrs that refer to the managed object 这个值在control block被创建时初始化为1，而后如果有weak_ptr weak reference this object,这个值会加1. 当最后一个shared_ptr dead时，会减1. 也就是number of weak_ptrs, plus 1 if there are any shared_ptrs outstanding。This can be understood as the number of things that are keeping the control block alive。 Doing it this way (instead of store this number as shread_ptrs+weak_ptrs) allows shared_ptr operations to avoid uselessly modifying the weak refcount ，it will simply be initialized to 1 and decremented by 1 upon the death of the last shared_ptr. if no weak_ptrs then, the number will be zero， the control block will be released. 还有另一种实现思路，这里只存储weak_ptrs的个数，不加一。那这时候判断是否需要释放control block就需要加锁了。比较容易出错。
使用
构造
  • 默认构造函数，会创建空shared_ptr,也就是不管理任何对象
  • 以指针为参数的构造函数，此类构造函数调用的时候，参数指针通常是new获得的，否则很可能使用错误
  • 拷贝或移动构造函数，都是以另一个智能指针为参数，或者与另一个智能指针共享managed object，或者获取另一个智能指针对managed object的所有权。
  • alias contructor

alias contructor

之前在内部实现中说到，一个shared_ptr其中存储了一个store_pointer和一个指向control block的指针。 control block中会存储指向对象的指针。 通常情况下，这个store_pinter和control block中存储的指针是同一个指针，但也可能不会相同。尤其在使用alias contructor的情况下。

//alias contructor
template< class Y >
shared_ptr( const shared_ptr<Y>& r, element_type* ptr ) noexcept;

// 移动构造+ alias contructor
template< class Y >
shared_ptr( shared_ptr<Y>&& r, element_type* ptr ) noexcept;

注意alias contructor的第一个参数肯定是一个shared_ptr。

通过这个构造函数，我们创建的shared_ptr与r共享 managed object 对象的所有权，control block中存储这个managed object对象的指针。而我们通过get操作，指针操作，解引用操作，是访问的第二个参数 ptr。也就是stored pointer . 这个ptr可能并不与control block中存储的managed object对象的指针相同。非常可能的情况是，ptr指向的是managed object 对象的某个数据成员。客户端操作shared_ptr仅仅只能操作这个成员。 Example:

std::shared_ptr<int> creator()
{
  using Pair = std::pair<int, double>;

  std::shared_ptr<Pair> p(new Pair(42, 3.14));
  std::shared_ptr<int> q(p, &(p->first));
  return q;
}

如上，q与p共享pair<int,double>(42,3,14)对象,但q访问的是这个pair对象的int成员。 这个函数返回后，该pair对象还存在，但我们通过返回的shared_ptr只能操作pair的int部分。

Example

#include <iostream>
#include <memory>

struct Foo
{
    Foo(int n = 0) noexcept : bar(n)
    {
        std::cout << "Foo::Foo(), bar = " << bar << " @ " << this << '\n';
    }
    ~Foo()
    {
        std::cout << "Foo::~Foo(), bar = " << bar << " @ " << this << '\n';
    }
    int getBar() const noexcept { return bar; }
private:
    int bar;
};

int main()
{
    std::cout << "1) unique ownership\n";
    {
        std::shared_ptr<Foo> sptr = std::make_shared<Foo>(100);

        std::cout << "Foo::bar = " << sptr->getBar() << ", use_count() = "
                  << sptr.use_count() << '\n';

        // Reset the shared_ptr without handing it a fresh instance of Foo.
        // The old instance will be destroyed after this call.
        std::cout << "call sptr.reset()...\n";
        sptr.reset(); // calls Foo's destructor here
        std::cout << "After reset(): use_count() = " << sptr.use_count()
                  << ", sptr = " << sptr << '\n';
    }   // No call to Foo's destructor, it was done earlier in reset().

    std::cout << "\n2) unique ownership\n";
    {
        std::shared_ptr<Foo> sptr = std::make_shared<Foo>(200);

        std::cout << "Foo::bar = " << sptr->getBar() << ", use_count() = "
                  << sptr.use_count() << '\n';

        // Reset the shared_ptr, hand it a fresh instance of Foo.
        // The old instance will be destroyed after this call.
        std::cout << "call sptr.reset()...\n";
        sptr.reset(new Foo{222});
        std::cout << "After reset(): use_count() = " << sptr.use_count()
                  << ", sptr = " << sptr << "\nLeaving the scope...\n";
    }   // Calls Foo's destructor.

    std::cout << "\n3) multiple ownership\n";
    {
        std::shared_ptr<Foo> sptr1 = std::make_shared<Foo>(300);
        std::shared_ptr<Foo> sptr2 = sptr1;
        std::shared_ptr<Foo> sptr3 = sptr2;

        std::cout << "Foo::bar = " << sptr1->getBar() << ", use_count() = "
                  << sptr1.use_count() << '\n';

        // Reset the shared_ptr sptr1, hand it a fresh instance of Foo.
        // The old instance will stay shared between sptr2 and sptr3.
        std::cout << "call sptr1.reset()...\n";
        sptr1.reset(new Foo{333});

        std::cout << "After reset():\n"
                  << "sptr1.use_count() = " << sptr1.use_count()
                  << ", sptr1 @ " << sptr1 << '\n'
                  << "sptr2.use_count() = " << sptr2.use_count()
                  << ", sptr2 @ " << sptr2 << '\n'
                  << "sptr3.use_count() = " << sptr3.use_count()
                  << ", sptr3 @ " << sptr3 << '\n'
                  << "Leaving the scope...\n";
    }   // Calls two destructors of: 1) Foo owned by sptr1,
        // 2) Foo shared between sptr2/sptr3.
}

get
element_type* get() const noexcept; //(since C++17)

A shared_ptr may share ownership of an object while storing a pointer to another object. get() returns the stored pointer, not the managed pointer.

#include <iostream>
#include <memory>
#include <string>

int main()
{
    auto output = [](std::string msg, int const* pInt)
    {
        std::cout << msg << *pInt << " in " << pInt << '\n';
    };

    int* pInt = new int(42);
    std::shared_ptr<int> pShared = std::make_shared<int>(42);

    output("Naked pointer: ", pInt);
//  output("Shared pointer: ", pShared); // compiler error
    output("Shared pointer: ", &*pShared); // OK, calls operator*, then takes addr
    output("Shared pointer with get(): ", pShared.get());

    delete pInt;

    std::cout << "\nThe shared_ptr's aliasing constructor demo.\n";
    struct Base1 { int i1{}; };
    struct Base2 { int i2{}; };
    struct Derived : Base1, Base2 { int i3{}; };

    std::shared_ptr<Derived> p(new Derived());
    std::shared_ptr<Base2> q(p, static_cast<Base2*>(p.get()));
    std::cout << "q shares ownership with p, but points to Base2 subobject:\n"
              << "p.get(): " << p.get() << '\n'

线程安全

shared_ptr不是线程安全的。多个shared_ptr,即使共享同一个对象，可以被多线程同时访问。但单独的一个shared_ptr，不能被多线程同时访问。 All member functions (including copy constructor and copy assignment) can be called by multiple threads on different instances of shared_ptr without additional synchronization even if these instances are copies and share ownership of the same object. If multiple threads of execution access the same instance of shared_ptr without synchronization and any of those accesses uses a non-const member function of shared_ptr then a data race will occur

enable_shared_form_this
template< class T > class enable_shared_from_this;

Publicly inheriting from std::enable_shared_from_this provides the type T with a member function shared_from_this. If an object t of type T is managed by a std::shared_ptr named pt, then calling T::shared_from_this will return a new std::shared_ptr that shares ownership of t with pt.

Notes A common implementation for enable_shared_from_this is to hold a weak reference (such as std::weak_ptr) to *this. For the purpose of exposition, the weak reference is called weak-this and considered as a mutable std::weak_ptr member.

The constructors of std::shared_ptr detect the presence of an unambiguous and accessible (i.e. public inheritance is mandatory) enable_shared_from_this base and assign the newly created std::shared_ptr to weak-this if not already owned by a live std::shared_ptr.

It is permitted to call shared_from_this only on a previously shared object, i.e. on an object managed by std::shared_ptr. Otherwise, std::bad_weak_ptr is thrown

enable_shared_from_this provides the safe alternative to an expression like std::shared_ptr<T>(this), which is likely to result in this being destructed more than once by multiple owners that are unaware of each other (see example below).

#include <iostream>
#include <memory>

class Good : public std::enable_shared_from_this<Good>
{
public:
    std::shared_ptr<Good> getptr()
    {
        return shared_from_this();
    }
};

class Best : public std::enable_shared_from_this<Best>
{
    struct Private{};

    // Constructor is only usable by this class
    Best(Private) {}


public:

    // Everyone else has to use this factory function
    // Hence all Best objects will be contained in shared_ptr
    static std::shared_ptr<Best> create()
    {
        return std::make_shared<Best>(Private());
    }

    std::shared_ptr<Best> getptr()
    {
        return shared_from_this();
    }
};


struct Bad
{
    std::shared_ptr<Bad> getptr()
    {
        return std::shared_ptr<Bad>(this);
    }
    ~Bad() { std::cout << "Bad::~Bad() called\n"; }
};

{
    // Good: the two shared_ptr's share the same object
    std::shared_ptr<Good> good0 = std::make_shared<Good>();
    std::shared_ptr<Good> good1 = good0->getptr();
    std::cout << "good1.use_count() = " << good1.use_count() << '\n';
}

        Good not_so_good;

    catch (std::bad_weak_ptr& e)

其他

The ownership of an object can only be shared with another shared_ptr by copy constructing or copy assigning its value to another shared_ptr. Constructing a new shared_ptr using the raw underlying pointer owned by another shared_ptr leads to undefined behavior.

std::shared_ptr may be used with an incomplete type T. However, the constructor from a raw pointer template<class Y> shared_ptr(Y*) and the template<class Y> void reset(Y*) member function may only be called with a pointer to a complete type (note that std::unique_ptr may be constructed from a raw pointer to an incomplete type).

The T in std::shared_ptr may be a function type: in this case it manages a pointer to function, rather than an object pointer. This is sometimes used to keep a dynamic library or a plugin loaded as long as any of its functions are referenced:

void del(void(*)()) {}

void fun() {}

int main()
{
    std::shared_ptr<void()> ee(fun, del);
    (*ee)();
}
