04 universal reference & reference collpsing 

int&& a =1;

这个int&&是右值引用

那么是不是所有的代码中&&都表示右值引用呢？不是的。 当需要编译器进行类型推导时，是万能引用。 比如如下

Widget&& var1 = someWidget;      // 这里的&&表示右值引用
auto&& var2 = var1;              // 这里的&&表示万能引用

template<typename T>
void f(std::vector<T>&& param);  // 这里的&&表示右值引用

template<typename T>
void f(T&& param);               // 这里的&&表示万能引用

第二种情况和第四种情况，&&表示的是万能引用， 第一种情况和第三种情况，&&是右值引用。 当&&表示万能引用后，编译器根据实际传递的表达式的value category做类型推导，如果是左值，就推导为左值引用，如果是右值，就推导为右值引用。所以第二个例子中，var2被推导为Widget&

  • auto&&
    Widget&& var1 = someWidget;
auto&& var2 = var1;
    第一个var1是个左值。 第二个auto&&,表示万能引用，但是我们用var1初始化var2, var1本身是个左值，根据当&&表示万能引用后，编译器根据实际传递的表达式的value category做类型推导，如果是左值，就推导为左值引用，如果是右值，就推导为右值引用。这个规则，编译器将auto&&推导为Widget&, 左值引用。
std::vector<int> v;
...
auto&& val = v[0];

这里我们初始化val的是 std::vector<int>::operator[]这个操作的返回值，该操作的返回值类型为int&, 之前说过，返回值为左值引用的是左值，也就是我们在用左值初始化 val, 所以这里的万能引用被推导为左值引用，int& val

  • 函数模板的模板参数
    template<typename T>
void f(T&& param);
    这里的param的类型完全是由编译器推导的，所以这里的T&&是个万能引用 。如果我们如下调用f f(10), 10是个字面值常量，是个右值，故而万能引用被推导为右值引用，也就是 f(int&& param) 。 如果我们用左值调用f
    int x = 10;
f(x);
    这时候这个param万能引用被推导为左值引用，也就是f(int& param)

&&只在需要编译器做类型推导时才是万能引用，如下

template<typename T>
void f(T&& param);               // deduced parameter type ⇒ type deduction;
                                 // && ≡ universal reference

template<typename T>
class Widget {
    ...
    Widget(Widget&& rhs);        // fully specified parameter type ⇒ no type deduction;
    ...                          // && ≡ rvalue reference
};

template<typename T1>
class Gadget {
    ...
    template<typename T2>
    Gadget(T2&& rhs);            // deduced parameter type ⇒ type deduction;
    ...                          // && ≡ universal reference
};

void f(Widget&& param);          // fully specified parameter type ⇒ no type deduction;
                                 // && ≡ rvalue reference

需要注意的是只有T&&这种形式的才是万能引用，如下的参数param依然不是万能引用

template<typename T>
void f(std::vector<T>&& param);     // “&&” means rvalue reference

哪怕添加了const限定符，也不再是万能引用

template<typename T>
void f(const T&& param);               // “&&” means rvalue reference

如下vector中的push_back声明,看上去是T&&,但不是万能引用

template <class T, class Allocator = allocator<T> >
class vector {
public:
    ...
    void push_back(T&& x);       // fully specified parameter type ⇒ no type deduction;
    ...                          // && ≡ rvalue reference
}

如果我们将push_back声明在vector之外，完整的声明如下(省去了第二个模板参数)

template <class T>
void vector<T>::push_back(T&& x);

编译器并不是对push_back的参数做类型推导，而是对vector的模板参数做类型推导。当vector的模板参数确定了之后，push_back的参数类型也就确定了，并不需要再推导。故而不是万能引用

vector中emplace_back的声明如下，这就是万能引用，虽然它的个数是可变的

template <class T, class Allocator = allocator<T> >
class vector {
public:
    ...
    template <class... Args>
    void emplace_back(Args&&... args); // deduced parameter types ⇒ type deduction;
    ...                                // && ≡ universal references
};

我们之前说过，左值，右值，是表达式值的属性，这个属性与表达式值的type无关。比如 10的type是int,但它是右值， int i = 0;, i的type也是int, 但它是左值。 如果是个用户定义的类型，比如Widget, 一个Widget类型的object也既可以是左值,比如 Widget i = Widget();,i就是左值。 也可以是右值，比如 getWidget(),这个函数返回一个Widget对象，这个对象是个右值。

因为表达式值的左值，右值的属性与表达式值的type无关，一个右值引用可以是左值，也可以是右值，如下

Widget makeWidget();                       // factory function for Widget

Widget&& var1 = makeWidget()               //var1是个右值引用，var1本身是个左值

Widget var2 = static_cast<Widget&&>(var1); // static_cast返回的也是个右值引用，这个右值引用本身是个右值(xvalue)

通常我们使用std::move将左值转换为右值，如下

Widget var2 = std::move(var1);

template<typename T>
class Widget {
    ...
    Widget(Widget&& rhs);        // rhs’s type is rvalue reference,
    ...                          // but rhs itself is an lvalue
};

template<typename T1>
class Gadget {
    ...
    template <typename T2>
    Gadget(T2&& rhs);        // rhs is a universal reference whose type
                             //will eventually become an rvalue reference or
};                           // an lvalue reference, but rhs itself is an lvalue

函数的参数本身永远是个左值，即使它的type是个右值引用。 在Widget的构造函数中，rhs的type是个右值引用，所以实际传递的参数必然是个右值，右值引用只能引用到右值。但是rhs本身却是个左值，如果我们需要实参的右值属性，则需要将rhs转换为右值，通常通过std::move实现。 同样的，Gadget中的rhs是个万能引用，所以最终调用的实参可能是个左值也可能是个右值，但不管是什么，rhs本身是个左值。如果我们想保留实参的左右值属性，比如实参是个右值，我们需要将rhs转换为右值，如果实参是个左值，我们保留其左值的属性。这是通过std::forward实现的。std::forward可以保留实际传递参数的左右值属性

  • reference collapsing

那么万能引用究竟是如何做到既可以被推导为左值引用，也可以被推导为右值引用的呢？ 引用折叠 虽然我们在代码中是不可以写 引用的引用的，如下

Widget w1;
...
Widget& & w2 = w1;

这是编译不过的。 但编译器却自己需要处理引用的引用这种情况，编译器处理引用的引用时，就会用到引用折叠。引用折叠有4中情况

& & -> &
& && -> &
&& & -> &
&& && -> &&

编译器在对万能引用的模板参数做类型推导时，同类型的左值和右值被推导成的实参类型是不同的， T 的左值被推导为T&, T的右值被推导为T. 如下

template<typename T>
void f(T&& param);

...

int x;

...

f(10);                           // invoke f on rvalue
f(x);                            // invoke f on lvalue

f(10)被实例化成 f(int&& param),这里的T被推导为int

而f(x),x是左值，T被推导为int&, f的实例化于是为f(int& && param), 这里的param就变成了引用的引用，这时候编译器做引用折叠，为 f(int & param)

这也就是为什么万能引用既可能会实例化为左值引用，也可能实例化为右值引用的原因。因为编译器自己可以做引用折叠。

如果传递的实参本身是个引用呢？模板参数会被推导成什么？一样的，引用变量本身是个左值。T被推导为左值引用。如下

int x;

...

int&& r1 = 10;                   // r1’s type is int&&

int& r2 = x;                     // r2’s type is int&

当我们用r1或者r2去调用f时，编译器会将type中的引用部分去掉，也就是将r1和r2都视为int, 然后r1, r2都是左值，T被推导为int& ,f的实例化为f(int & param)

auto&&的类型推导过程同模板参数推导过程一样，如下

Widget&& var1 = someWidget;      // var1 is of type Widget&& 

auto&& var2 = var1;              // var2 is of type Widget&

在var2的类型推导时，var1 type中的引用部分被去掉，var1被是为type Widget. 因为var1是个左值，故而被推导为左值引用Widget&， 然后应用引用折叠，var2的类型为Widget&

typedef也可能会导致引用折叠的发生，如下

template<typename T>
class Widget {
    typedef T& LvalueRefType;
    ...
};

and this use of the template,

Widget<int&> w;

the instantiated class would contain this (invalid) typedef:

typedef int& & LvalueRefType;

Reference-collapsing reduces it to this legitimate code:

typedef int& LvalueRefType;

If we then use this typedef in a context where references are applied to it, e.g.,

void f(Widget<int&>::LvalueRefType&& param);

the following invalid code is produced after expansion of the typedef,

void f(int& && param);

but reference-collapsing kicks in, so f’s ultimate declaration is this:

void f(int& param);

也就是说，引用折叠不仅会发生在万能引用的推导过程中，在很多地方，只要是引用的引用，编译器都会做引用折叠。只是我们不能在程序代码中写引用的引用。

最后看个例子总结下

//万能引用
#include <iostream>
using std::cout;
using std::endl;

//T& 是个左值引用，只能引用左值
template <typename T>
void func(T& t){
    cout<<"call func"<<endl;
}

//T&&是万能引用，可能引用右值，也可能引用左值。如果引用右值，被推到为右值引用，如果引用左值，被推到为左值引用
template <typename T>
void func2(T&& t){
    cout<<"call func2"<<endl;
}

int main(){
    //func(1);  不可用右值实例化

    int i=1;
    func(i); //实例化成 func<int>(int&)

    int && ri=1;
    func(ri); //ri本身是个左值，实参推导时，type的引用部分被去掉，实例化成 func<int>(int& )
    int & li = i;
    func(li);  // 实例化成 func<int>(int&)

    func2(1); // 实例化成 func2<int>(int &&)
    func2(i); // 实例化成 func2<int&>(int &)
    func2(ri); //ri本身是个左值，实例化成func2<int&>(int&)
    func2(std::move(ri)); //move返回右值，实例化成func2<int>(int&&)
    func2(li); //实例化成 func2<int&>(int&)
}
